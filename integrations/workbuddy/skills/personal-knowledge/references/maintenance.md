# 日常维护、引导与管理

## 日常检查

只在宿主调用本 Skill 或已授权的知识库任务中检查，不声称在其他对话、关闭的客户端或后台持续观察。

先按 [文件变更](changes.md) 核对未读历史与任务，再读共享目录，按需要分页。检查与当前用途有关的缺口：资料是否还在处理、是否失败或部分解析、目录是否待更新、是否有重要事实候选或冲突。没有问题就使用现有结果，不重跑所有资料。

| 状态 | 合适的动作 |
| --- | --- |
| 已有 queued/running 的整理任务 | get_job 查看，不再次触发同类任务；本轮最多三次短间隔查询后返回真实进度 |
| 自动整理已开启，新增资料正处理 | 等现有入库和增量任务完成；不重复导入或重新生成目录 |
| 需要补齐存量，或用户明确要求整理 | organize_catalog → get_job → read_catalog，核对同一目录 ID、修订和实际变化 |
| 自动整理暂停 | 保持暂停。只有“这次整理一下”等明确请求才单次执行，不顺带恢复自动开关 |
| 某来源变更或撤回 | 使用当前有效来源；不引用已失效摘录或旧表单结果 |
| 一次重跑无变化 | 报告跳过未变资料即可，不新建目录副本，不编造“整理了多少篇论文” |

目录维护保护已有人工字段。复杂语义专题是另一类生成成果；只在当前任务确实需要时创建，证据齐全且不能把旧专题说成自动更新成功。

## 帮用户逐步丰富知识库

在有用的时机提出一项高价值补充建议：

- 当前表单因缺少某项依据无法完成：说明缺的是哪项及最合适的材料。
- 多次询问同一项目，资料零散：建议补一份原始项目总结或相关记录。
- 新材料与旧履历冲突：请用户确认有效时间或提供更直接的依据，不按上传时间决定谁对。
- 用户完成一个阶段：可建议收录最终版成果或复盘；没有收录授权则先问。

区分“阻止当前任务完成的缺口”和“有空再补的材料”，优先前者。不要为追求所谓完整档案索要一整套个人信息；不要随意给出知识库完整率。用户拒绝、不方便或说以后再说，就继续当前任务。

个人字段缺失只说明当前已采纳档案中没有可用值，不证明原始资料里没有；必要时先检索，再决定是否向用户索要。

## 管理请求

| 用户请求 | 当前处理 |
| --- | --- |
| 看目录、找资料、看原文 | read_catalog、list_sources、search_knowledge、read_source、read_evidence |
| 改目录标题、分类、摘要或备注 | 明确修改目标及内容；当前 MCP 无编辑工具，引导网页“编辑目录标题与备注”或“编辑条目”，完成后读目录核对 |
| 恢复自动内容 | 引导目录条目的“恢复自动内容”；它保留备注，不等于删除原件或取消事实采纳 |
| 修改个人信息、处理冲突 | 提取并核验后用 accept_knowledge_facts 采纳结构化候选，标记 Agent 操作；不覆盖人工修正/拒绝，冲突保持待核对；用户独立声明仍走网页 |
| 删除某份资料或释放空间 | 读 get_storage_usage；提出具体清理方案，由用户在网页批准后执行，见 [空间维护](storage.md)；也可直接使用网页“我的资料”的“撤回并删除资料” |
| 删除后核查 | 重新读目录和相关来源；不可访问即不再引用。仅目录隐藏不能证明后台原件清理已全部完成；没有清理状态工具就标明未独立核验 |
| 下载原件 | 引导资料原文窗口的“下载原件”；当前没有全库打包导出工具 |
| 暂停或恢复自动整理 | 引导目录的“自动整理新增资料”；已排队任务仍会完成，恢复后补齐差异 |
| 撤销 Agent 访问 | 引导“连接 WorkBuddy”撤销对应令牌；不展示、复制或重新签发凭据 |
| 全库重置、共享或迁移 | 先明确范围和影响；当前没有对应 MCP 能力，不能用单份删除或文本导出冒充；批量清理每批最多 20 份且需要具体方案授权 |

用户要求管理某件事不自动包含清理其他资料。尤其不要自动删除“疑似重复”、旧履历和冲突材料。

## 日常执行与真正的计划任务

“平时帮我维护”可以在本 Skill 被调用时按已授权范围检查。若用户明确要求按时自动执行，需要真实的宿主调度器、知识库身份、任务范围、时间/时区及失败/取消方式；先查实际能力，再创建和验证。

当前 MCP 没有调度工具。没有可用宿主调度器时，给出可保存的任务描述并明确尚未启用。不能只写一句 Skill 指令就报告“已设置每天自动整理”。

## 检索、材料与填表

目录用于选资料；read_source/read_evidence 用于核对，保留原文定位。当前词法检索的 top-k 不能替代全量统计。

填表先 get_profile/read_knowledge 再 prepare_form，写入前 read_form_draft，处理 ready/missing/conflict/blocked。候选、统计与 Word 流程见 [语义整理任务](semantic-tasks.md)。仅在用户明确允许该草稿使用联系方式时设 allow_sensitive=true。缺失不填零，冲突不猜；资料变化后重新准备草稿。

任何继续操作第三方网页的动作，都按当前任务的目的地、字段和用户授权判断。知识库管理和表单草稿不等于对外披露或提交许可。
