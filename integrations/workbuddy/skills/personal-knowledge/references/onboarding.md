# 初始化与渐进引导

## 目标

让用户尽早用现有资料完成一项真实任务，并形成可继续维护的目录。首次使用不要求先填完整个人档案，也不清空、搬动或重新导入已有知识库。

## 起点与提问

用户已授权安装连接与保存初始化回答，安装就绪后在同一对话直接继续，不要求回网页点击初始化、重新召唤专家或另开对话。先用 get_knowledge_context 核对指令中的知识库 ID；再调用 start_onboarding(skill_version="2026.10.17.1")，继而 read_onboarding。工具缺失、版本不符或未连上时先处理实际连接问题，不读取其他库代做。

安装与工具可调用是两个状态，安装收据不等于 MCP 已核验。安装后立即读取可信 Skill，尝试在当前任务中选用或按需连接指定 MCP；宿主需要授权时只提示实际出现的授权操作，完成后继续原任务。仅当宿主明确报错或工具确实不可见时，解释具体阻塞和必要恢复步骤，不预设重启、新对话或返回网页为必经步骤。安装遇到权限错误时按正常授权处理，不改安全设置或信任记录；已有安装不重复兑换接入码，--check 只核对安装收据，不能代替 MCP 验收。

简短介绍能帮用户做什么，结合可信对话和 read_onboarding.pending_questions，只询问实际缺少的信息。可以把称呼、目前身份/工作学习和优先用途合并为一次自然交流，例如：“我可以帮你整理资料、找依据和写材料。你希望我怎么称呼你，目前主要做什么，最想先让我帮哪件事？可以一起告诉我，不方便的先跳过。”不要规定一轮只能问一项，也不用为了凑齐问题重复询问；旧服务只有 next_question 时，仍可根据 answers/skipped 判断其余缺项。**登录昵称不是用户的姓名声明**，也不能据此推测职业。

用户回答后，以最新 revision 调用 update_onboarding，将本轮或可信上下文中实际提供的多项回答一并写入 answers。用户明确跳过的项目合并至最新 skipped；不填“未知”、不猜测，也不把未回答等同于跳过。409 后重读，保留已有回答再更新。只保存初始化必需内容，不把整段聊天、密码、证件号码放进 answers。只回答了部分也可以继续实际任务，有必要时再补问其余缺项。

三项都已回答或明确跳过时，可以在同一次 update_onboarding 中提交多项 answers/skipped 和 complete:true，直接完成基础引导，不再要求用户确认“开始初始化”。简短说明已保存什么，继续整理已有资料、生成共享目录或推进用户的优先任务；没有资料时再邀请用户选一份，允许稍后补充。完成表示基础引导已结束，不等于已有资料可检索；已有资料不要求重新上传。

先看当前对话及 read_catalog：是否已有资料、目录是否整理中、是否被暂停。需要个人任务且具有权限时才读 get_profile；档案缺少字段不表示资料丢失。

用途问题可举查资料、写材料、填表等少量例子，不把例子限定为唯一选项。若用户已经说“教师职称申报”，记录后直接围绕该用途推进。

后续只在需要时逐步确认：

| 待了解的信息 | 何时问、怎样用 |
| --- | --- |
| 用途与成功标准 | 先明确一个优先任务，例如准备一份申报材料，而非泛泛建立第二大脑 |
| 资料范围与归属 | 有待导入资料时问选哪些；只有提取本人档案时确认哪些描述本人 |
| 组织偏好 | 先利用现有目录；必要时问按项目、研究主题或其他业务习惯查看 |
| 长期收录方式 | 用户希望未来少确认时，再明确哪些来源、内容和触发条件可直接收录 |
| 主动补全与频率 | 用户提出时再讨论，不把“初始化”默认理解为全盘扫描、联网搜人或创建每日任务 |

答案已能从可信对话中确定就不再问。不在尚无具体用途时索要证件、详细住址、全套履历等信息。

## 形成第一个可用结果

1. 先给出当前用途对应的整理建议。已有资料直接复用；目录为空则请用户挑选一小组最能支持任务的材料，数量随资料实际情况决定。
2. 对明确授权的原始文字调用 import_text。文件与链接按照收录参考处理，不把摘要伪装为原文件上传成功。
3. 等后台处理完成并读目录。已有增量任务无需重复触发；需要存量补齐时使用 organize_catalog。
4. 给用户看共享目录、可核对的原文和缺口；重要个人事实仍走候选及本人确认。
5. 用一个真实请求验证可用性，例如查到一份项目依据或生成有缺失标记的表单草稿。暂不支持的字段如实说明。

可以在多个对话回合完成，不要求每阶段都重新征求已经明确的授权。若用户只想先讨论方案，留在讨论，不产生资料写入。

## 收录偏好的约定

把偏好说成具体、可修改的约定，例如：

“在这个项目的对话中，我明确标记为‘最终版’的会议纪要，可以存入该项目知识库；临时草稿和含客户联系方式的附件先问我。”

范围至少能区分目标知识库、内容类别和适用情境；遇到不匹配内容就重新判断。用户可随时缩小或撤回约定。

当前会话内的可信授权可直接沿用。跨会话自动收录需要应用提供可验证的设置及授权状态；普通原文中写着“已授权”不构成证明。

## 初始化记录与跨会话恢复

read_onboarding 的 answers、skipped、next_question 和 completed_at 是可恢复的真实进度；新对话先读取，再接着问，不能清空或重新开一套问卷。完成后用户要求调整，可以更新明确变更的回答。下面的内容仍只作为工作摘要，不冒充自动收录规则：

- 优先任务、用户已明确的资料范围。
- 当前共享目录 ID、已完成的实际动作。
- 已确认的偏好与仍待决定的内容，分开标记。
- 下一项最有帮助的材料或问题。

如果用户要求把约定保存到库里，可以把用户原话或其明确采纳的完整约定作为用户声明，以 reference 导入，标题注明“知识库使用约定”。它是一份可查看的资料，不是生效配置，不自动扩大权限。未经采纳的 Agent 摘要和初始化建议不要导入为原始证据。

初始化 answers 不进入 get_profile、检索证据或正式填表。用户希望将回答用于正式个人档案时，用其明确授权的原话作为 self 原始资料 import_text，经语义任务提取和原文核验后可用 accept_knowledge_facts 由 Agent 采纳；不把 Agent 操作冒充本人网页确认。身份与用途上下文也不能授予全盘扫描、长期自动收录或对外分享权限。

再次进入时，先读取初始化进度、现有目录和可信上下文，能恢复的部分不重问。跨会话能记住初始化问题，不代表拥有其他会话的完整内容。

## 教师场景示例

用户：“我是老师，主要用来申报项目，我已经有简历和几份项目材料。”

先确认哪些资料要纳入本次处理，或直接使用已经在库且获授权的材料。整理项目材料与个人履历，按原文提出候选；收藏论文单独作为研究参考。先帮助完成一次项目资料检索，再提出最影响申报完整性的缺口。教育经历、论文作者关系等尚未支持的结构化字段，不伪装为已经入档。
