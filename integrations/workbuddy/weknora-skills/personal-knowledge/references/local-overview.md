# 扫描后的进度与资料概览

用户选定范围后主动扫描，利用同一个知序连接保存结果并回读。只读核对、暂不检索和用户要求暂停时遵从当前任务范围。

## 更新扫描进度

1. 用本机脚本的 `scan` 回执或 `status` 核对实际覆盖，区分完成、部分覆盖、目录离线和已有旧缓存。以最新回执为准，不能用目录条目数推算已解析文件数。
2. 用 `read_library` 和 `read_library_item` 找到本次初始化对应的既有 `episode`。例如原条目写着「等待指定资料目录」，而该任务确已建立索引，就沿用其 key 和当前 revision 更新，说明已完成的操作、覆盖范围类型、已索引和仅文件名可检索的数量、后续从哪里继续。没有对应条目时使用 `local-documents-progress-<device_id>` 新建。旧缓存缺少回执时写「已有本机索引」，不写「已完成全量扫描」。
3. 用 `save_library_item` 写入后按返回的 id 回读，确认正文和 revision。进度只记录操作事实，可使用空的 source_versions。遵守用户当前的只读要求与人工修改保护。

## 自动保存概览

1. 通过 `status` 确认当前启用范围的 publish_summary=true，或用户已明确授权保存本次该范围的概览并据此更新本机配置。概览与原件收录、文件清单共享分别授权。已有明确授权就继续，同一轮不再次询问。
2. 用本机 `search QUERY --titles-only` 选取与当前用途相关的代表性资料，再用 `read` 和哈希核对正文。没有指定用途时选不同类型的工作材料，先查标题再读取必要片段。优先少量代表材料，默认最多核对 8 份。排除凭据、联系方式、第三方简历和申请表、测试样例；不能仅凭文件名归纳主题。
3. 把有正文支持的主题和可用场景写成 3–6 条简短导航。例：「课程材料包含讲义和考试复习资料，可用于查课程结构」。区分已扫描覆盖与本次样本范围，注明按当前设备的本机索引重新检索。省略私有路径、文件清单、原文摘录、联系方式和未经归属核实的个人事实。无法从样本可靠归纳时只更新任务进度。
4. 用 `save_library_item` 保存一条标题为「本机资料概览」的 `episode`，key 为 `local-documents-overview-<device_id>`，source_versions 与 citations 留空。正文标注「本机检索导航，原件未收录」；它用于下次定位资料，正式写材料或填表前应重查并核对实际来源。需要带正式出处的知识页时，按原件收录流程获得云端来源及证据后再写 `page`。
5. 写前按 key 查重；同一设备已有概览则比较正文，内容有变化才用当前 revision 更新。409 先重读合并，保留人工修改，重试同一请求沿用 request_id。写入成功后调用 `read_library_item` 核对 id、版本和正文，向用户给出「知识目录」的条目名称。失败时明确说明索引状态和概览保存状态。

后续处理同一设备的资料时复用上次授权。增量扫描发现相关资料变动后只修订受影响的主题。目录停用或缩小范围时，使用最新状态，不再将旧概览当作当前覆盖；用户可在知识目录修改或遗忘已保存的概览。
