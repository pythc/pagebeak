# 多格式个人资料盲测验收

日期：2026-10-17。结论：**部分通过**。真实 WorkBuddy 完成了读取资料、整理知识页、浏览器保存草稿、填写 Word；28 个字段经人工语义复核通过 27 个，仍有证据范围推断错误，不能判为完全可靠的自动填报。此记录独立于此前陈舟合成文本验收。

## 样本和隔离

构造虚构教师“林知远”的 9 份原始文件：3 份 DOCX、2 份 XLSX、3 份 PDF（含 1 份纯图片扫描证书）、1 份 TXT。人物信息散落在履历、聘任通知、结题纪要、教学台账、成果登记、证书、收藏论文、复盘备忘录及邮件中。全部人物、机构、成果及编号均为虚构。

样本含旧职称和旧邮箱、已录用但未发表论文、同名作者收藏、重复成果、统计期外课程、计划未完成课程、他人教学工作量、团队奖排名、参与项目与主持项目的区别，以及缺失个人信息。已知答案与文件 SHA-256 在运行前冻结；不向被测 Agent 提供答案或评分脚本。

资料通过知识库上传 API 进入独立合成租户。WorkBuddy 通过单独的 `persona-acceptance` stdio MCP 读取，未使用真实用户库或外网检索。其任务目录仅含指令和空白网页/Word 模板。网页只监听 `127.0.0.1:5882`，保存草稿至本机，不向外部单位提交。

说明：这是受控单人样本。部分来源明确标出了同名作者、重复导出等提示，不能将本次表现外推为真实杂乱资料的总体准确率。

隔离边界是知识库租户与任务指令，WorkBuddy 仍处于“允许完全访问”模式；本轮不是强制文件系统沙箱的安全验收。答案和评分文件未发送给模型，实际观察到的人物证据来自指定 MCP；内置 Office 工具的技术说明读取不作为额外人物知识来源。

## 文档解析与修复

首轮预检实际发现两份 Excel 解析失败：有效 XLSX 可以省略可选的工作表 `dimension`；原实现直接比较 `max_row/max_column` 与整数，遇到 `None` 发生异常。另外，首列空白时不能从第一个单元格读取行号。

修复 `backend/akb/parsing.py`：缺少尺寸时先以流式 XML 扫描确定边界，再有界读取；保留原有 20,000 行、200 列限制，使用行迭代序号保持稀疏单元格定位。增加缺少尺寸、隐式坐标及超限回归用例。自行复核了稀疏坐标、边界检查及工作簿关闭路径。全部 64 项后端测试通过；已有 Starlette TestClient 弃用警告 1 条。

修复后重新创建独立租户并上传冻结样本：9 份均完成解析，3 份 `ready`、6 份 `partial`，共 62 条证据。`partial` 表示基础解析范围有限，不能描述为完整支持所有 Office 布局。扫描证书经 RapidOCR 得到 10 行文字，奖励、排名和日期可读。

## WorkBuddy 真实执行

客户端为 WorkBuddy 5.8.3，模型选项 Auto，最终回复显示 `Hy4 preview`。有效任务显示“已完成 12m48s”。通过客户端 MCP 编辑器保存并启用独立连接，工具显示 23/23；实际调用 7 类工具、18 次 HTTP 请求，其中 17 次成功、1 次知识页保存因超过 30 条引用上限失败后重试成功。工具可用数量不代表全部实际调用。

首次任务没有加载独立连接，模型违反限定，改用了旧 `personal-knowledge` 的陈舟资料。验收方发现后取消。该轮记为连接选择/指令遵循失败，不算林知远验收通过。之后通过 UI 正确启用连接、正常退出并重启客户端，用新任务重新运行。

重跑中已独立核验：目录/来源读取、全部 9 份原文读取、关键词检索、表单草稿准备、证据读取、带引用知识页保存。知识页 ID 为 `a5854d2c-93c1-4ed2-8bd4-1e23cdc89787`，关联 30 条证据，API 重读确认均来自冻结样本。第一次保存失败，随后重试成功。

后端结构化档案的 6 个标准字段仍没有已采纳事实，`prepare_form` 返回缺失。此次资料使用普通叙述，现有标签抽取不能自动建立这些事实。因此必须区分“Agent 阅读证据后能填写本机草稿”和“后端自动抽取已完成”：后者未通过。Agent 没有通过 MCP 擅自确认事实。

浏览器填写并保存本机草稿已实际完成，保存编号 `1792186193897080000`。表单服务端收到 28 个资料字段与备注，WorkBuddy 导出了实际浏览器截图。严格比对通过 26/28；研究方向的“知识检索、教育数据分析”与“知识检索与教育数据分析”语义一致，人工复核计通过，故语义复核为 27/28。该数字仅指本受控样本的 28 个字段。

失败字段：行政职务。模型填“无”，但原文只说明本次专业技术聘任不涉及行政任命、本人不是系主任，不能推出不存在其他行政职务。此项应保留未知。知识页中“无已任命行政职务”的结论也存在同一证据范围问题；保留原始产出，不以人工改写制造通过结果。

测试页自身另有一项失败：Python 模板中的换行转义生成了非法 JavaScript，导致第一次点击原生 GET 提交、字段清空。这是验收设施错误，不计为模型识别错误。已保存错误脚本，用 `node --check` 确认错误后修复并验证语法，再重启同一地址。WorkBuddy 自行重新打开页面，最终使用 CSS 选择器与逐步验证完成浏览器保存；未用直接 POST 替代浏览器动作。

Word 已逐页渲染复核：原稿 4 页，人工保留意见单独占第 4 页。另附验收方整理的 3 页排版副本，仅调整段间距、行距和标题分页约束；逐段及表格单元格文字完全一致，未改变内容或首轮成绩。原稿和全部模型产出另存 `首轮原始输出/`。正文“主持教务处项目”的归口信息没有明确原文依据，来源仅为教务处项目验收组，应在正式提交前删除该归口限定或补证；原稿未人工替换此措辞。

独立评分脚本曾因 `form-*.json` 同时匹配验收记录文件而读取错文件；已限定为数字保存编号，并要求 28 个字段键齐全后重新评分。此为评分设施修复，未更改冻结答案或模型产出。

目录摘要未选入教学台账 A5 行；原始证据中该行完整存在。WorkBuddy 实际重读全部原文，正确将其纳入 160 学时、246 人次。该例说明摘要用于导航，不能替代完整证据进行汇总统计。

## 后续优先修复建议

1. 对“未知”“明确没有”“不属于某特定身份”建立不同状态，写入前检查结论范围；此次行政职务错误同时传播到了网页、JSON 和知识页。
2. 为普通叙述资料增加语义候选抽取，先保留证据和待确认状态，再由用户采纳；不要仅靠 `姓名：…` 等固定标签，也不要用模型自行确认绕过采纳流程。
3. 缺少指定 MCP 时应立即停止，不能改用其他连接；客户端和入口应明确展示当前租户与知识库，防止第一次失败重现。
4. Word 在标记完成前增加真实逐页渲染检查。本受控任务实际模型处理 12m48s，后续应评估日常操作的延迟和交互成本；不把本次单样本正确率当成产品总体水平。
