# 校园教师助理 0.9.0：实现、验收与上线边界

日期：2026-10-26。用户确认：暂时没有可认证的企业或学校发布主体，先做普通 WorkBuddy 助理；模型用量由教师自己的 WorkBuddy 账号承担，资料服务部署在学校机器。

## 产品与教师操作

采用 WorkBuddy 专家（对教师显示“知序教师助理”）+ Skills + 远程 MCP。暂缓 Buddy 应用，不依赖其企业开发者认证。共享包只含说明和服务地址，教师身份在安装后通过本人登录授权绑定，不能把开发者的令牌、知识库编号或本机 Python 路径塞进公共包。

发布后的教师流程：安装官方 WorkBuddy 并登录 → 打开学校核验过的助理安装入口 → 在学校资料页面登录并允许连接 → 回到同一对话介绍身份与用途 → 上传第一份材料并整理。不强制逐题提问、不要求回网页点击初始化；已有回答继续保留。

教师无需安装 Python、Docker、数据库或填写模型密钥。WorkBuddy 的订阅与模型用量属于教师自己的账号；学校仍承担文件空间、解析、存储、备份和运维成本。当前没有把 WorkBuddy 登录凭据当后台 API 使用；无人执行 WorkBuddy 任务时，后台只解析和同步原文，语义归纳等待下次 Agent 执行。

**目前尚未发布正式安装入口。** 预览包使用 `documents.example.test` 和 `preview@example.test`，不可直接发给教师。生成 ZIP、原生格式校验通过、协议验收和真实客户端模型验收是不同阶段。

教师版说明见 [教师助理试点指南](教师助理试点指南.md)，生成的网页是 `/teacher-assistant-guide.html`。原 Mac 本机版 `/zhixu-guide.html` 继续保留；开始页根据实际接入模式选择教程。

## 接入实现

- `AKB_ASSISTANT_PUBLIC_ORIGIN` 为空时保留原本机 stdio 接入；配置后才挂载共享 OAuth/MCP。正式值必须为 HTTPS 根地址；HTTP 仅允许 loopback 本机验收，不从请求 Host 自动推断地址。
- 标准授权服务元数据、资源元数据、公共客户端动态注册、S256 PKCE、显式账号授权、授权码单次使用、1 小时访问令牌、30 天刷新令牌及撤销。仅存令牌摘要，不把密码交给模型。
- 文件账号通过现有 Cloudreve 登录态核验。授权页 nonce 与实际用户绑定；换账号或重放旧页面会被拒绝。用户资料继续走原有数据库强制行级隔离。
- 远程 MCP 的每次调用独立携带本人令牌和库 ID；不修改进程环境变量实现账号切换。同步调用在线程执行，避免回调到本进程 API 时阻塞主事件循环。
- 远程提供 27 个工具，包括可信 Skill 读取、知识目录、原文、整理、证据和填写校验、初始化以及文件空间上传入口。**不暴露服务器磁盘的扫描、读取和本机路径上传工具。** 原本机 35 工具不移除。
- 远程助理的 `local_documents.available=false`。已有本机索引沿用单独组件；多平台本机组件尚未完成。不能把校园服务器扫描结果冒充教师本机资料。
- 只有真实认证后的 `start_onboarding` 才记录已观察到的接入。浏览器允许授权不直接标记初始化完成；升级和刷新保留已有回答与完成状态。

公共包构建命令：

```bash
.venv/bin/python scripts/build_teacher_assistant.py \
  --origin https://替换为学校实际域名 \
  --author-email 替换为发布者实际联系邮箱 \
  --output outputs/teacher-assistant/正式构建目录
```

使用真实 ASCII 域名、真实联系邮箱替换示例后再运行；命令只生成包，不发布。构建器拒绝覆盖不同内容，包内文件排序与 ZIP 元数据固定。最终上架仍需登录 WorkBuddy 平台完成审核，并从普通教师账号实际验收。

## 校园服务器与部署选择

已依用户指示联系线程“工单系统”，取得已有 SSH 方式，并于 2026-10-26 19:00（北京时间）重新只读核对：Linux x86_64，Docker 29.1.3，5876、5878、55471、8420、8421 当时均空闲；`/data` 可用约 865 GiB。共享机器负载有波动，端口、容量和容器网段都必须在实际上线前再次检查。未改其他项目的代理、容器、卷或数据库。

准备了 `deploy/campus/Dockerfile` 和 `compose.app.yaml`：固定 Python 镜像摘要、uv 版本、腾讯源码提交、Node 与 SQLite 原生模块校验和；应用用非 root 账号及资源限制。compose 合并检查通过，应用容器不挂载 Docker socket，也不挂载主机 `.env`，变量由 compose 注入。

**该应用镜像目前仅完成运行时验收，不是完整校园部署交付。** 现有 Office 在线预览会调用宿主机 Docker 创建一次性隔离转换容器；把 API 直接搬进不含 Docker socket 的应用容器后，这条预览路径不可用。镜像里存在 LibreOffice 不代表这条路径已接通。不能为了省事把宿主机 Docker socket 直接交给应用。

校园正式试点优先保留现有隔离转换方式：在专用 Linux 服务账号的 Python 3.12 环境运行 API/Worker/腾讯运行时，文件服务与数据库继续使用独立 Docker 项目；或先交付受限转换执行器再采用全容器应用。选择后须实际验收 Word/Excel/PPT 在线预览、超时清理、资源限额和回滚，当前均 **NOT_RUN**。

部署前还缺固定 HTTPS 地址、实际发布者联系信息和原生客户端验收。学校网络需让教师电脑上的 WorkBuddy 能访问该地址；模型在校外不表示 MCP 服务必须暴露给整个公网。反向代理应把 `/mcp`、`/.well-known/*`、`/register`、`/authorize`、`/token`、`/revoke`、`/v1/*`、`/v2/*` 分发给知识 API，其余文件页面与 `/api/v4/*` 保持文件服务；不得把认证请求统一回退到 SPA。

## 上线与回滚顺序

1. 在新目录准备独立运行环境、私有配置、数据库角色和存储，不复用其他项目卷；备份 PostgreSQL、Cloudreve 数据、腾讯数据与私有配置。先验证恢复，不能只检查备份文件存在。
2. 备份后显式执行 `alembic upgrade head`，核对 0022，再启动；启动器不会自动迁移。
3. 配置实际 HTTPS 的 `AKB_ASSISTANT_PUBLIC_ORIGIN`、同源 `AKB_NATIVE_ORIGIN` / `AKB_WEB_ORIGIN` 和安全 Cookie。先以合成教师测试登录、授权、续期、撤销、目录、增量、人工保护、上传与 Office 预览。
4. 用真实域名和发布者联系邮箱重新生成助理包，从原生 WorkBuddy 完整验证后才提交发布。不向教师发送本预览包或任何管理凭据。
5. 灰度少量教师；观察解析失败、空间、模型任务耗时与费用，再扩大试点。

回滚先关闭共享接入开关并撤销相应授权，再回退已备份的静态资源或保留 0022 兼容性的应用版本。0022 是添加授权表，不自动删除历史；其 downgrade 显式拒绝破坏性回退。**不能直接启动只认识 0021 的旧版本绕过版本栅栏**。如确需数据库恢复，停写后在独立环境验证备份与应用一致性，再按维护窗口恢复，不能在线覆盖。
