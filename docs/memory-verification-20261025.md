# 腾讯 Memory 的填写校验、出处与恢复加固

日期：2026-10-25。知识正文仍由腾讯 MemoryKnowledge / MemoryCore 保存；WorkBuddy 当前模型负责理解。以下为本机实现及验证，不是生产就绪声明。

## 已实现

### 计算与填写

`prepare_filling` 接收目标字段、原始记录、筛选属性和原文锚点。服务验证数字、单位和事项编号的原文支持，按编号去重、排除不匹配记录，使用 Decimal 求和、计数及元/万元换算。冲突值、未知筛选属性、不兼容单位、无依据的零值及暗中舍入均拒绝。无依据字段使用 unknown 并输出空字符串。

受控事迹段由已检查字段组合生成，不新增自由改写的事实。`validate_filling` 比较实际网页或 Word 回读与准备值，检查缺字段、多字段和值变化。回执仅保存哈希与来源清单，24 小时到期；来源上传、解析状态变化、修改、删除均使旧回执失效，包括尚未解析的新上传文件。

边界：计算只覆盖模型提交的记录，不能证明模型没有漏选；模型仍须判断字段含义、身份、时间与口径。回读校验不能独立证明浏览器保存或 Word 落盘，必须另外检查实际产物。受控段落也不等于任意文章均有语义校验。

### 原文出处

`resolve_fact_evidence` 验证租户、来源版本、证据片段、原文起止位置，允许受限的 Unicode 显示等价差异并返回原始字符。有歧义的重复片段须显式指定起点。知识页可以携带逐条 citations；正文从腾讯读取，本地仅保留引用定位和状态，不建立第二套事实正文库。

目录页面可展开结论对应的文件名、位置和原文；人工编辑保留仍有效的出处。来源变化时停止将旧页当作当前事实；原有人工修改与历史页保留。未标注的旧页明确提示补充出处。

边界：锚点校验只能证明引用确实存在，不证明结论在语义上必然成立。citations 不是所有页面的强制字段，历史页面不会因此自动获得认证。

### 运行可靠性

- 原生写入前记录私有日志，提交 PostgreSQL 后移除。失败或进程中断留下的正文由后台对照登记表清理；故障注入覆盖未登记的 Core/Wiki 正文和原文导出。
- 原文导出采用不可变版本文件名。知识页登记其引用的原生文件，清理时保护人工页及历史页引用，避免腾讯 raw 删除连带删掉保留的页面。
- 回读校验正文哈希，服务故障返回错误，不以空结果冒充成功。短中文专名用当前已登记原生内容的字面查找补充 BM25。
- 后端配额包括原件及腾讯逻辑内容字节。该统计不包括 SQLite、索引、WAL 等磁盘开销；Cloudreve 原生侧边栏仍显示文件服务配额，尚未统一为两者总占用。
- 新迁移 0019 / 0020 为增量结构；旧表保留。新接入包 0.7.1，MCP 27 个工具，知识契约 `tencent-workbuddy-v4`。

## 同资料新旧盲测

使用单独旧引擎实例（冻结原代码、独立数据库、38 工具）与当前腾讯引擎（独立租户、26 工具）。两侧均导入相同的 9 份新合成资料，逐字核对 57 个原文片段及定位一致。标准答案和输入哈希在模型执行前封存。资料类型为 DOCX、CSV、Markdown、TXT，本轮不额外声称覆盖扫描件/PDF/XLSX/PPT。

统一契约包含 22 个普通字段、1 个事迹段；统一网页和 Word 模板。预设重复记录、同名他人、参考论文、完成/取消/计划、主持/参与、批准/到账/支出、元/万元精度、录用/发表、缺失个人信息和文件内注入指令。

第二阶段使用同一新增聘任通知，并先注入相同的人工备注。两侧分别在新会话中恢复、增量整理、重填新产物，检查历史结果和人工修改保留。输入目录与目标模板对模型开放，答案和另一版本结果不开放；这属于任务约束盲测，不是操作系统强制隔离。

**实际执行已完成原始 A/B 第一阶段和目录增量阶段。** 旧版网页/Word 均为 20/22，金额归一化错误；腾讯版第一阶段因表头单位关联能力缺失而阻塞，不能给出填写准确率。目录增量阶段腾讯版恢复了人工备注，旧版漏读。缺陷已修复，真实 WorkBuddy 填写回归完成，独立评分网页和 Word 均为 22/22，受控事迹段和全部 1 页视觉检查通过。最终表头与重新解析专项 19 项通过，重启后真实 MCP 重放及实际产物回读通过。回归用时 27 分 26 秒，含模型超时和参数纠正，尚不能称为稳定顺畅的产品体验。
