实施日期：2026-10-17。本地开发实现，未发布生产环境。

**后续调整：用户明确要求恢复 Cloudreve 原版前端，再逐项决定保留、删除和新增功能。自建文件页已撤下，当前“我的文件”直接打开原版中文页面，使用独立演示账号；原版上传暂不自动入库。下文为上一轮历史实现与验收，当前状态见 [恢复记录](native-frontend-restore.md)。**

## 交付范围

“我的资料”已改为“我的文件”。采用本项目自己的 React 界面，通过服务端连接 Cloudreve **4.19.1 社区版**，没有嵌入原版网盘页面或复制其前端源码。

| 保留 | 实际行为 |
| --- | --- |
| 文件夹、面包屑、文件列表 | 新建、重命名、移动文件夹；禁止循环和超过 100 层；仅删除空文件夹 |
| 文件名搜索 | 跨当前账号全部文件夹查找，回收站单独查找；分页显示 |
| 上传与下载 | 2 GiB 上限、8 MiB 分块、容量预留、中文下载名称、Range 下载 |
| 文件操作 | 重命名保留扩展名、批量移动、回收、恢复、明确确认后的彻底删除 |
| 内容查看 | 解析状态、摘要、带页码/段落/单元格位置的原文预览，下载原件 |
| 容量 | 已用、总量、回收站占用、接近满时进入空间管理；管理员继续按人分配 |
| 知识整理 | 上传后自动解析、增量更新共享目录；人工摘要和批注保留 |

用户界面不提供分享链接、公开空间、商城、购买套餐、离线下载、WebDAV 配置、第三方挂载、Cloudreve 用户设置和管理后台入口。第一版也没有增加收藏、最近使用、网格切换、在线 Office 编辑等次要功能。

本阶段内容预览是**解析后的文字与摘要**。后续已在原生文件空间增加本地转换的 Office 只读预览，见 [在线预览](online-preview.md)；Office 在线编辑仍未接入，复杂布局与旧版 Office 的解析限制仍见 [空间与 OCR 记录](storage-and-ocr.md)。

## 与调研建议的调整

社区版配额主要依赖用户组，直接开放完整 Cloudreve 登录和写入路径会建立第二套身份、配额及删除入口。本项目已经有个人配额、上传预留、RLS 和删除授权，因此采用私有存储网关：

```text
用户 / WorkBuddy → 知序账号、权限、个人配额、回收站与知识服务
  → PostgreSQL：文件夹、Source ID、证据、人工修改、清理授权
  → Cloudreve 私有网关：原件字节
```

- Cloudreve 仅监听 `127.0.0.1:5878`，无公网和用户侧入口，公开注册关闭。
- 后台使用独立的**非管理员存储账号**，只开启文件操作、WebDAV、代理与彻底删除所需组权限。凭据放在 Git 忽略的 `secrets/`，文件权限 0600，不返回网页或 Agent。引导管理员凭据单独保存，仅供操作员维护。
- 用户继续用现有知识库账号，无需第二次登录、OAuth 或商业版 OIDC。
- 个人容量以知识库租户账本为准。Cloudreve 内部组的 1 TiB 是聚合服务上限，与个人套餐无关；所有产品写入必须经过网关。
- 文件夹结构存于知识库数据库，Cloudreve 使用 `akb/<tenant UUID>/<source UUID>` 不变键。重命名和移动无需搬大文件、重做 OCR 或更换资料 ID。
- **新原件写入 Cloudreve，旧原件保留本地位置，没有批量搬迁或删除旧数据。** `object_key` 前缀决定适配器；没有长期保存两份原件。
- 这是本项目的私有存储后端，不是已有 Cloudreve 站点的同步客户端。不开放外部直接写入，也不承诺监听外部更改，因此本轮没有部署 SSE 订阅；开放外部写入前需另做版本、权限与周期对账协议。

## 回收站与删除

移入回收站同事务撤回资料访问、取消未完成解析与旧清理授权、递增知识修订。检索、证据、个人事实支持、专题和表单草稿立即停止使用这些来源。原件、证据数据与人工目录字段保留，文件继续占用容量。

恢复保留 Source ID、原文件夹、目录条目 ID、人工标题、摘要和批注。中断解析重新排队，证据重新可见；旧表单草稿仍需重新生成。

彻底删除先撤回访问，再由后台删除原件和知识依赖。Cloudreve 返回成功且原路径不可读取后释放个人原件配额；**底层物理实体由 Cloudreve 自己的回收任务异步清理**。个人可用容量与宿主磁盘即时空闲量不是同一指标。合成 2 GiB 删除后，本次容器数据目录已回落到不足 1 MiB。

Agent 无本次新增文件管理接口的写权限，不能通过批量操作跳过授权。Agent 清理继续走“提出具体方案 → 网页授权 → 执行”的现有流程。

## 故障行为

- 存储上传失败返回中文 503；数据库回滚，不增加已用容量，分块暂存与预留保留。网页当前会话可重试保存或取消暂存；24 小时到期由 Worker 回收。跨页面重载的恢复面板未实现。
- 下载流式代理，不把 2 GiB 读入内存，不向浏览器返回带后台凭据的直链。关闭下载压缩，避免长度与 Range 不一致。
- Worker 流式下载临时原件并核对 SHA-256、长度和临时磁盘空间，再调用现有解析子进程；临时文件随上下文删除。存储异常走有限重试，不发布未核验的解析结果。
- 发布前写入原子故障日志，数据库提交后移除。进程崩溃残留原件可由维护脚本检查；默认仅报告，`--apply` 才回收超过 24 小时、无数据库引用且哈希一致的失败上传。
- 删除失败不释放配额，后台重试。未提供清空全部文件或数据库破坏性降级。

## 启动与维护

先完成 README 的本地数据库及依赖初始化：

```bash
docker compose --profile cloudreve up -d cloudreve
uv run python scripts/setup_cloudreve.py
```

在被忽略的 `.env` 中设置 `AKB_CLOUDREVE_CREDENTIALS` 为 `secrets/cloudreve.json` 的绝对路径，执行 `uv run alembic upgrade head`，构建前端并重启 `scripts/dev.py`。引导脚本仅用于此项目独立的 Cloudreve 卷，已有凭据文件时不覆盖。

镜像固定为 `cloudreve/cloudreve:4.19.1@sha256:5c6c5baf7fa5bc6e1bb9a7509c09dde00e80b618d180244eb1d5f7e36b358ea2`，使用独立 `akb_cloudreve` 卷，不挂载旧对象目录，不启动离线下载器。Cloudreve 沿用上游 GPL-3.0 许可与署名；分发其二进制应随附对应许可及源码获取信息：[上游源码与许可](https://github.com/cloudreve/cloudreve/tree/4.19.1)。

```bash
uv run python scripts/reconcile_cloudreve.py          # 只报告
uv run python scripts/reconcile_cloudreve.py --apply  # 核对并回收失败上传残留
```

移除配置可使新上传改用本地存储，但已有 Cloudreve 原件仍需要正确配置和运行服务才能读取。停止容器、删除卷不能实现无损回退；本轮没有执行旧原件的全量迁移。

- **48 项测试通过**：PostgreSQL、隔离、文件夹循环、搜索、重命名/移动、上传目标、Agent 权限、回收引用撤回、人工修改恢复、容量释放、存储故障和上传幂等；包含真实 Cloudreve 上传、解析、Range 与删除用例。

- 运行中 API 实际上传 Word、Excel、PPT、图片、扫描 PDF、CSV、Markdown，生成证据、摘要、目录并检索通过。OCR 事实仍需确认。
