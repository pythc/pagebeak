# 资料目录：实现与验收

日期：2026-10-17。范围：本地开发版，合成资料。

后续更新：自动摘要已从文件开头摘录改为跨全文原文抽样，算法为 document-extracts-catalog-v2；共享目录新增有损摘要归档。本文保留 v1 验收记录，当前能力与限制见 [空间与 OCR](storage-and-ocr.md)。

## 用户与 Agent 使用同一份目录

网页默认打开“资料目录”，按分类显示资料标题、原文摘录、人工摘要/备注、处理状态和原文依据，支持分类跳转、分页、编辑和恢复自动内容。页面下方可展开本页 Markdown。

目录有一个稳定 ID。网页调用 GET /v1/catalog，Agent 通过 MCP read_catalog 调用同一服务，返回相同修订的结构化数据和 Markdown；不是两份独立生成的目录。个人介绍只在调用方有 profile:read 权限时返回；人工摘要不能替代原文事实。

## 主动与增量

- 升级通过 0003 为现有租户建立目录并排入存量整理任务，后台自行执行；新账号独立初始化。
- 新资料接收、解析完成、解析失败及撤回时，同一事务排入整理任务；同租户已在排队的任务合并。
- 后台比较算法版本、来源版本、生成批次、状态等指纹。只为变化的来源重新读取最多三个原文块，每块最多 320 字符，其余条目保留 ID、生成时间和用户修改。
- 目录维护不调用模型，不要求 WorkBuddy 保持打开。当前为四类规则分类与原文摘录，不冒充通用语义摘要、实体归并或模型自主规划。
- 网页可暂停后续自动任务，重新开启时补齐存量差异；暂停前已排队的任务仍完成。手动“整理现有资料”或 MCP organize_catalog 可单次执行，不会偷偷开启自动开关。
- 无变化的重跑不增加目录修订号，不重复生成专题，也不改变个人事实版本或使表单草稿失效。

## 人工修改保护

目录标题/备注，以及条目标题、分类、摘要、备注分别保存于 manual；后台只更新 generated。人工值优先展示；恢复自动内容删除对应覆盖值，但保留用户备注。网页只保存真正改动的字段，避免编辑备注时意外冻结自动标题。

网页修改使用 expected_revision；后台或另一窗口先修改时返回 409，编辑草稿保留。用户可核对最新目录后显式刷新版本再保存。MCP 不提供人工修改入口，不能把 Agent 输出伪装为用户确认。

目录及条目由 RLS 和来源复合外键隔离。来源撤回立即从读取结果中移除，不等待后台清理；暂停自动整理也不影响清理目录里的摘录和人工条目内容。来源变化但尚未重建时，旧自动摘录不再返回。

## 队列与升级

复用持久化任务表，organize 任务不绑定单份来源。任务发布检查租约、工作进程和 fencing token，在租户锁下原子更新。解析任务崩溃并耗尽重试时，0004 的调度函数额外排入目录刷新，避免目录一直停在等待解析。

0001/0002 保持原样；新增 0003/0004 为前向迁移，不重建原始资料。当前库升级通过；全新临时数据库升级至 head 并与 ORM schema 对比通过。破坏性 downgrade 保持禁用。

## 实际验收

沿用上一轮隔离 WorkBuddy 合成账号，既有三个原始来源：

- 陈舟个人履历（合成验收）.txt
- 知序项目材料（合成验收）.txt
- 收藏论文笔记（合成验收）.txt

后台自动整理形成目录 ID：5da18dc8-9c81-499c-be9f-712475c00a1f，初次修订 2，三份资料、三个分类。

随后通过真实网页修改目录标题和备注，并把项目条目的标题改为“知序项目 · 人工整理标题”、分类改为“教学与项目”，添加人工摘要和备注。修订到 4。

通过实际 stdio MCP import_text 新增“知序项目补充（增量验收）.txt”，来源 ID：85123780-e4f2-421c-89dd-48ccd262602e。未再次手动要求整理，后台自动更新同一目录到修订 5：

- 总资料数从 3 增至 4；本轮 sources_read=1、unchanged=3。
- 三个旧条目的 ID 与生成时间保持不变；目录及条目的六项人工修改全部保留。
- 网页 API 与 MCP 相同分页参数下的 JSON 完全一致；所有返回摘录及定位经原文 API 重读核对。
- 再调用 organize_catalog，sources_read=0、unchanged=4，修订和条目不变。
- 浏览器实际检查新增条目、人工分类与备注；点击目录原文依据能定位到项目材料第 1 行；展开 Markdown 可看到相同目录 ID、修订 5 和全部四份资料。

32 项自动化测试通过，包含存量整理、分页、增量跳过、人工修改保留/恢复、409 冲突、来源更新、删除与暂停、权限隔离、表单有效性、任务合并、旧租约拒绝及最终重试恢复；保留既有的一条 Starlette TestClient 弃用提示。Ruff、前端 TypeScript/Vite 构建及新库迁移检查通过。

## 边界

已实现的自动整理是文件目录、原文摘录及当前已采纳信息的展示。更深的语义主题组织、跨文档关系、完整论文实体、OCR、网络补全与生产规模验收仍待实现；没有新增后台模型凭据或假设 WorkBuddy 的登录模型可由服务器调用。原件与既有专题没有迁移为新事实，也没有 Git 提交、推送或生产发布。
