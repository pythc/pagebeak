# WorkBuddy 第二轮盲测记录

日期：2026-10-17。本轮是隔离合成账号的本地验收，结论为**部分通过**。原始资料整理、网页与 Word 填写、新资料增量及人工修改保护均已执行。产品代码在本轮基线验收期间保持不变。

## 方法与边界

独立创建虚构教师许清禾的八份办公资料，事实间接分布于申请、聘任通知、工作量表、论文跟踪表、项目纪要、扫描证书、阶段回顾和邮件中。包含历史职称/邮箱、同名他人、参考资料、重复事项、取消/计划课程、团队排名、项目经费与未获批准计划等干扰项。标准答案与源文件 SHA256 在模型启动前冻结，放在不向模型提供的 `private/`，任务要求仅通过 `blind-v2` MCP 读取人物知识。

这是任务约束下的盲测，未通过操作系统沙箱阻断模型访问其他本地文件，不能证明物理隔离。验收方 Codex 持有答案并负责后续候选复核；该复核是模拟合成用户确认，不是 WorkBuddy 的自主确认，也不能据此计算模型准确率。

WorkBuddy 5.8.3 使用其自身模型。本轮新增独立知识库与限权 MCP，保留其他连接器和账号。用户手动发送第一、第二、第三阶段启动句，因为当前原生窗口自动化无法可靠输入；实际读取、候选提交、首轮草稿生成、浏览器填写和 Word 撰写由 WorkBuddy 执行。MCP 收据只记录时间、方法、路径和成功状态，不记录令牌或请求正文。

八份材料解析出 41 个原文块；两份状态 ready、六份 partial。基础 Office/OCR 解析不代表完整复杂版式支持。扫描证书的八行内容经实际 OCR 并逐项检查。

资料由验收程序通过知识库上传 API 入库，本轮没有重新验证 Cloudreve 前端上传链路。Word 的两页由验收方另行渲染并逐页检查，不能仅凭模型声称生成成功就视为版式通过。

## 网页四个未通过项

| 字段 | 标准答案 | 实际保存 | 原因 |

| 2025 年本人已完成课程学时 | 86 | 空白 | 后端把已拒绝的取消/计划课程纳入实体分组，过滤字段未确认导致整体聚合 missing |

| 本人主持且已结题项目 | 可追溯课程检索工具 | 1 | 模型将名称字段映射为 count，后端返回就绪的数量，目标字段没有类型约束 |
| 该项目立项经费，单位元 | 75000 | 7.5万元 | 数值含义正确，未转换为目标表单要求的元格式；严格判为格式未通过 |

14/18 包括四个应留空字段。这个小样本通过率不能代表一般用户资料的准确率。模型遵循非 ready 不填的约束，因此教学统计没有被臆造补齐，但产品端到端任务仍未成功。

Word 的八个模板字段与同一后端草稿一致，正文正确区分本人主持与参与、已发表与已录用、已完成与未批准计划，逐项对比原文未发现虚构主要业绩。但“2019 年 6 月取得博士学位”被改写为“2019 年 6 月毕业”，后者并非原文明示，不能当作严格等价的事实通过。课程学期等细节也未建模为独立已确认字段；当前没有逐句绑定确认记录的机制，不能宣称自由撰写部分已被系统强制限制为确认事实。人工备注只被原样保留，未被伪造成原件证据。Word 因教学合计缺失、语义改写与确认门禁限制，判为部分通过。它是增量前的原始产出，后续聘任变更不会自动修改已经下载的文件。

代码复核发现 `backend/akb/knowledge.py` 的 answer 从 live_facts 分组时未排除 rejected；choose 又不会采纳 rejected，从而使只有被拒绝事实的实体产生过滤问题。多条件过滤还会在某字段已明确不匹配后继续记录其他未知字段，令不相关事项污染合法项目的结果。模型首轮项目筛选因此返回 missing/conflict，缩小到具体实体后才得到值。

## 增量实际验证

冻结首轮网页与 Word 文件及 SHA256 后，验收方通过合成账号浏览器会话 API 模拟用户将单位改为“东岑应用技术大学（主校区）”，并为第一份申请资料添加“人工备注：增量更新仍须保留本行。”。随后上传一份新聘任通知，原文明示自 2026-10-01 起聘任教授，不涉及其他岗位。

后台只增加一个待整理任务，跳过原有八份资料。WorkBuddy 实际领取、读取三个原文块并提交两条 candidate：职称教授、单位东岑应用技术大学，两条 valid_from 均为 2026-10-01。范围说明没有被扩张为“没有行政职务”，也没有臆造副教授的终止日期。

WorkBuddy 实际读取旧草稿并观察到 stale=true、answers=[]；增量导出的 read_knowledge 和 read_catalog 与同分页 API 完全一致，含 65 条可见知识与 9 份来源，其中两条仍待确认。模型报告正确识别并保留人工单位与备注。

验收方再模拟用户采纳这两条候选，之后通过浏览器会话 API 生成三字段校验草稿，验证当前姓名许清禾、单位东岑应用技术大学（主校区）、职称教授，待确认数为 0。这最后一步是验收程序检查，**不是 WorkBuddy 再次调用 MCP，也不是更新后的第二次网页/Word 填写**。增量前下载的 Word 不会自行更新，必须重新生成后才能用于新时点。

本轮按任务指令启动 Agent，没有验证资料一到就自动唤醒 WorkBuddy。后台可主动创建待办，但真实 Agent 的持续运行/定时唤醒与周期巡检仍待实现。资料目录的规则分类仍偏粗，九份资料中七份为“其他资料”；按七种知识类型的结构化目录已可读，但不能据此宣称完成了高质量语义主题编目。

## 修复建议（本轮未修改产品实现）

1. 聚合前排除不参与候选计算的 rejected/superseded 记录；实体已被明确条件排除后，不再将其缺失字段计为全局问题。用本轮反例覆盖回归。
2. 为教学增加状态、为联系信息增加完整性属性，使取消/计划事项和脱敏号码可以保留知识且不能误填。
3. 为表单定义目标字段类型、单位与操作：项目名称只能接收 title/value，数量接 count，金额统一返回元并保留原始值/转换依据。
4. 在填写前展示字段映射预览，校验标签、选择器和目标类型一致；即使后端返回 ready，也不能跳过目标语义校验。
5. 自由事迹按句绑定证据与确认状态，源文件有依据和用户已确认是两个不同条件；未确认的细节只进入待确认事项。
