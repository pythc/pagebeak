# 腾讯 Memory 与旧版：同资料实际验收

日期：2026-10-25。本报告区分原始盲测、发现缺陷后的修复与回归。评分由验收 Agent 独立读取已保存产物并对照预先封存答案完成，不是用户本人审核。

## 测试条件

- 旧版：冻结实现，独立数据库与 API 5879，38 个 MCP 工具。
- 腾讯版：MemoryKnowledge / MemoryCore 保存正文，WorkBuddy 执行理解与写入；原始轮 26 个工具，修复后 27 个。
- 两版均在 WorkBuddy 5.9.1 中选择“快速”；四次原始会话的实际模型字段均为 `glm-5.3-flash`。每个版本、每阶段只跑一次，不构成统计性能结论。
- 同一批新合成人物许沐宁的 9 份工作资料，原件哈希一致，初始解析的 57 个原文片段及定位一致；第二阶段增加同一份聘任通知。DOCX、CSV、Markdown、TXT；本轮没有新增 PDF/OCR/XLSX/PPT 场景。
- 22 个普通字段与 1 个受控事迹段；同一 HTML 表单和 DOCX 模板。涵盖重复记录、同名他人、参考资料、计划/取消/完成、主持/参与、批准/到账/支出、元/万元、发表/录用、未知信息、文档内恶意指令。
- 答案在执行前封存。模型只获自己的 agent-space 和 MCP；未观察到读取答案或另一版本结果。此为任务约束盲测，没有操作系统级隔离；宿主已有其他工具与连接。旧版额外写了本任务的宿主 memory 日志，未观察到后续跨任务读取。不能声称绝对隔离。

旧版将原文 `1.275 万元` 采纳成 `amount_yuan=1.275`，导致合计填成 93452.025 元 / 9.3452025 万元；正确值为 **106200.75 元 / 10.620075 万元**。其填写校验通过，证明草稿与产物一致；没有证明错误归一化后的事实是真实的。

腾讯版被我们自己的填写接口卡住：CSV 表头含单位，数据行只含数值，二者属于不同证据块；旧接口没有同列表头关联参数。模型连续尝试修改参数仍失败，由验收 Agent 在 16 分 17 秒点击停止。客户端显示“用户取消”，实际不是人类用户主动取消。停止前的目录、调用、错误与未完成产物已封存。

原始盲测不能得出“腾讯版全面胜出”，也不能把受控计算回执等同于语义正确。

## 修复与独立回归

1. CSV、Excel、Word 简单表格保留真实单元格列位置及空列。长行分块不伪造完整列映射。
2. 填写行新增 `unit_evidence` 与 `value_column`，验证同来源版本、同表/工作表、第一行表头与数值列一致；拒绝跨来源和错列。数字与原单位需直接关联，不能从别处找“元”来为“万元”数值背书。
3. 支持明确无量纲的整数单值（例如排名），金额与求和仍必须有单位；按字段批量返回校验错误，不签发部分回执。
4. 新增 `reparse_source`：复用有持久化任务和版本栅栏的解析队列，保留原件及人工页，立即使旧出处和填写回执失效；重读后重新关联证据。
5. 技能明确要求汇总结论引用全部纳入行，不能以第一行引用冒充完整合计证据。新包 0.7.1，知识契约 v4。

工程验证：24 项解析/表头/金额专项通过；175 项普通回归通过、8 项真实服务测试按开关跳过；14 项真实服务与计算专项另行通过；Ruff 通过。重新解析专项验证了原件哈希不变、旧回执失效、人工正文保留。

**实际 WorkBuddy 修复后回归完成：网页 22/22、Word 22/22。** 两份保存产物由验收 Agent 独立读取并对照预先封存的增量答案评分。正确得到 106200.75 元 / 10.620075 万元、84 学时、100 人次、3 门课程；未知行政职务/电话/毕业日期留空。受控事迹段与正确字段一致，未发现新增无依据事实。Word 全部 1 页已渲染检查；模板结构、固定文字、人工备注保留，无残留占位符。

新知识页 revision 5，36 条当前出处，汇总教学/项目/论文的结论引用了全部纳入记录。人工备注仍为 revision 1、protected=true，旧阶段本地文件哈希全部不变。三份 CSV 原件保持原哈希，经正常重新解析后绑定新的出处。

本次使用 GLM-5.3-Flash，**27 分 26 秒、74 次工具调用**（含宿主计划/文件工具）；出现模型响应超时自动重试、一次 MCP 参数结构拒绝、一次后端金额表头绑定拒绝。模型自行纠正后才完成。结果通过不代表体验已流畅或运行耗时稳定；减少大参数重复生成和支持更小计算批次是后续重点。

最终代码复查又加严了表头单位判定：优先括号内明确单位，不把“人数（人次）”标签中的“人”误作单位，并拒绝同列“元/万元”歧义。最终专项 **19 项通过**。重启当前服务后，通过真实 stdio MCP 重放**原模型未修改的计划**，同一回执与两份独立读取产物仍完全一致；这是确定性回归，不是新的模型盲测。此前普通回归 175 通过、8 跳过，真实服务/计算专项 14 通过的结果分别留存，不混加成一次测试数字。安装的两份自有管家技能已备份并同步，新契约 v4；未修改凭据和信任设置。

### 旧版增量填写续测

目录阶段封存后另起会话完成增量网页与 Word，旧引擎代码未改动。实际两份产物均为 **20/22**：当前职称正确更新为副教授，两项总金额仍沿用原错误。Word 1 页、固定文字与人工备注保留，全部旧产物哈希不变。填写与回读中 3 次使用问题已记录（故事截短、网页结构读法、Word 标签映射），最终回读一致；一致性仍不代表总金额正确。

此续测共 42 次工具调用。虽然界面仍选“快速”，底层记录中同时出现 `glm-5.3-flash` 和 `deepseek-v4.1-flash`，因此补充轮不是严格固定模型的 A/B 实验。原始四次会话仍只有 GLM。窗口控制一度报错，发送状态未及时确认；恢复后核对发现任务已实际发送并完成，没有重复发起。

## 证据及限制

证据根目录 `work/memory-ab-20261025/results/`。四份 `*-frozen/freeze.json` 保存原始产物、来源快照与调用记录哈希；独立评分保存在 `*-evaluation.json`。首次输入和标准答案位于私有验收目录，不下发给模型。

- 引文存在只是定位核验；没有通用自然语言蕴含证明。复杂改写、材料遗漏与字段含义仍依赖模型及复核。
- 计算只覆盖提交记录；不能自动发现漏读的数据。缺失不等于零。
- 回读校验本身不能证明浏览器已保存，必须检查浏览器操作、保存回执与文件。
- 表格关联只覆盖有完整列定位的简单单行表头，复杂合并/多行表头不保证可处理。
- 原生存储恢复演练覆盖 PostgreSQL、腾讯数据和本地原件；未复制外部 Cloudreve 文件卷，不是全产品灾备验收。
- Cloudreve 侧边栏配额尚未统一包含腾讯数据；多机、多实例、生产规模、全部故障时点尚未验证。
