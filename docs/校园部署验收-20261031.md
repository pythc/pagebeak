## 实际遇到的问题与处理

1. Mac Docker Desktop 返回 OCI 索引 ID，服务器 Docker 返回配置对象 ID。初次直接比较二者失败；修正为验证已核验归档中的配置摘要、平台和全部 diff_ids，未跳过校验。
2. PostgreSQL 18 首次启动对 PGDATA 子目录降权，但挂载父目录为 root:root 0700，造成非 root 阶段无法进入。按固定镜像实际 postgres UID/GID调整本应用挂载根目录，模式保持 0700，随后正常启动。13 次历史重启保留在容器记录中，不能描述为零重启。
3. systemd 的 UMask=0077 将预览临时输入目录变成 0700，隔离转换器以 nobody 运行而不能读取。显式设置仅被只读挂载的 input 子目录为 0755，输入文件为 0444，外层私有工作目录仍为 0700。12 项预览回归及真实服务器中文转换均通过。保留 0.13.3-r1，修复以 0.13.3-r2 发布。
4. 运行验证脚本最初缺少 ZIP 顶层目录前缀，随后用了镜像未安装的 fitz；已按包实际结构及已锁定的 pypdf 修正，保留失败记录，不将测试工具问题归为应用故障。
5. 开始页硬编码浅色背景与深色主题的浅色文字冲突。改用主题背景与文字颜色；Vite 构建通过。首次代理更新后探测过早，发布脚本自动回滚到 r2；增加就绪等待后再次发布通过。旧标签由 Service Worker 提示更新，不将旧画面当成新版视觉通过。
6. 真实网页上传后的解析子进程报 ModuleNotFoundError: akb。WeKnora 镜像仅复制源码、依赖 PYTHONPATH，子进程过滤环境时误删该路径。修复为从可信模块自身推导源码根目录及 cwd，仍不继承凭据或任意 PYTHONPATH；相对原件路径先解析为绝对路径。
7. WorkBuddy 注册新专家后，旧对话继续缓存旧 localhost MCP，模型据旧库状态错误宣告连接成功。已停止该对话，保留失败证据。0.13.4 增加 expected_service_origin、service_origin 和安装提示中的地址核验；已有设备空间的安装请求同时固定库 ID。宿主需从原生新对话/连接授权加载新地址，不能仅依赖连接同名。

8. 0.13.4 初次发布将 WeKnora 一并重建，90 秒发布超时触发回滚；回滚也在依赖就绪前超时，造成短时入口不可用。WeKnora 随后自行健康，未重置数据；已单独恢复 app/proxy 并核对 200。0.13.4-r1 将 WeKnora 镜像独立固定，应用更新和回滚只更新 app/proxy，发布前后核对 WeKnora 容器 ID 与启动时间不变。保留失败和恢复日志。
9. 重启 WorkBuddy 后仍有旧连接，进一步只读核对确认存在历史手动同名 MCP（localhost:5890），不是单纯对话缓存。0.13.5 使用规范服务地址的摘要生成稳定连接名，不删除或覆盖旧手动连接；包内 MCP、技能、初始化请求和服务返回技能保持一致。29 项授权、接入、跨来源隔离回归通过。

10. 本机打包渲染器的后备字体缺少中文字形；未修改模型输出，也未把 XML 回读当视觉通过。将同一 SHA-256 的 DOCX 交给校园 Office 预览 broker，回读中文并检查一页 PNG，布局通过。
11. 模型多次漏传 lease_token、混淆原始单位和目标单位、提交不匹配的引文标点。它能自行恢复，但明显增加执行成本。回执 valid 不等于自由改写已通过语义认证。
