# 可核对的知识层：实施与验收

日期：2026-10-17。范围：本地开发环境 `http://localhost:5876/`；Cloudreve 原生页面 `http://localhost:5878/`。原件、已有资料、目录人工覆盖和文件变更记录保留。本轮未提交 Git、推送或部署生产。

## 已实现

工作流为：原件解析 → 当前原文版本的语义整理任务 → Agent 提交带出处的候选 → 用户确认或修正 → 共用知识目录、个人档案、填写草稿与 Word。

| 能力 | 当前实现 |
| --- | --- |
| 资料与知识目录 | 保留资料目录；新增“知识目录”和“待处理”页签，覆盖个人信息、任职、教育、论文、项目、教学、荣誉。API、MCP 和网页使用同一投影及修订号，提供 Markdown。 |
| 事实与出处 | 记录主体、本人/参考归属、事项标识、字段、值、肯定/否定/明确不存在、有效日期、原文引用、证据 ID、原件哈希及解析版本。 |
| 未知与否定 | “不是系主任”只否定系主任，行政职务保持未知；“没有找到资料”不产生“无”。整体不存在必须有相应原文并经用户确认。 |
| 人工修正 | 修正形成独立的用户声明，覆盖自动候选；原文更新或删除后保留。原候选及决策有记录，修订不一致时拒绝覆盖。 |
| 增量任务 | 每个来源的每次解析版本建立一份任务。原文变化后旧任务不可提交，旧证据立即退出填写；重试有请求标识、版本检查和租约，重复请求不重复新增。 |
| 时效与冲突 | 有明确生效日期的新标量事实可以取代较早事实；没有时间依据的相互矛盾记录不会强行覆盖。历史及冲突在目录可见，冲突阻止填写。 |
| 统计 | 程序按本人归属、已确认过滤条件和规范化事项标识去重，计算数量、金额、学时、人次；值或单位不明不计算。不宣称覆盖现实中的全部成果。 |
| 填写 | 网页与 Word 共用一份有修订号的草稿；未知、冲突、未授权联系方式留空。Word 模板支持 `{{field:job_title}}` 及中文字段 key，保留其他正文、样式和人工备注。 |
| 版本失效 | 资料或知识变化使旧草稿及生成页面失效；旧答案/正文停止返回，要求重建。当前使用租户级修订号，可能连带使无关草稿失效。 |
| 连接身份 | MCP 固定 `AKB_EXPECTED_KB_ID`，每次操作由 API 核对，库不匹配停止。语义候选确认仅能通过本人网页会话完成，MCP 不能自行批准。 |
| 任务可见性 | Cloudreve 原有任务看板增加等待 Agent 整理数量和知识目录入口，未改变原生文件列表布局。 |

语义处理需要 WorkBuddy 或其他连接的 Agent 执行。后台能够自动发现新材料并建立任务，没有配置可用模型执行器时显示“等待 Agent”；这不是已经实现无人值守的模型常驻服务。Skill 已更新相应领取、分页阅读、提交、确认和重读步骤。

## 实现位置与迁移

- `backend/akb/knowledge.py`、`knowledge_schema.py`、`knowledge_api.py`：知识选择、任务、校验和统一 API。
- `backend/akb/form_document.py`：从当前草稿填写 Word 标记，拒绝过期草稿及未知模板字段。
- `web/src/KnowledgeView.tsx`、`CatalogView.tsx`、`App.tsx`：共用目录、审阅及填写入口。
- `backend/akb/mcp_server.py`：29 个工具。新增 context、knowledge、task list/claim/submit 和 draft read。
- `integrations/workbuddy/skills/personal-knowledge/references/semantic-tasks.md`：执行流程与能力边界。
- 迁移 0012～0014：知识任务、事实、决策、支持证据和生成页面依赖；已在本地现有数据库应用，也通过全新临时数据库迁移和 ORM 对照检查。

部署需先升级数据库，再构建网页并重启 API/Worker；WorkBuddy 需重连 MCP 加载新工具和固定库 ID。旧数据不删除，后台对开启自动整理的目录补建任务。历史生成页无版本时标记过期，不作为现行填写依据。当前实现尚未进行生产数据升级/降级演练。

## 合成场景与可复现输入

使用虚构教师“李若晴”，事实分散在聘任 Word、工作回函、教学核对和重复复核记录中。新聘任通知作为增量资料加入；另加研究说明用于实际网页确认。不是把人物标准答案作为一份原文直接导入。

仓库内保留五份协议验收原件和空白 Word 模板：`integrations/workbuddy/demo/knowledge-layer-fixtures/`。第六份网页验证资料为：“虚构研究说明：李若晴目前的研究方向为知识检索。”

| 场景 | 预期与实际 |
| --- | --- |
| 候选未确认 | 不进入正式填写；通过。 |
| 局部否定 | “不是系主任”没有被填成“无行政职务”；行政职务留空；通过。 |
| 重复与他人资料 | 本人两门课程 48 + 32 = 80 学时；同一课程重复复核不叠加，同事 96 学时不计入；通过。 |
| 增量更新 | 加入 2026-10-01 聘任通知后只有一份新任务；确认后当前职称从副教授更新为教授；通过。 |
| 人工修改 | 手动单位“澄川大学”、目录标题“聘任材料 · 人工命名”和备注均保留，新增来源中的旧单位没有覆盖；通过。 |
| 过期草稿 | 更新前草稿返回 stale，旧答案为空；旧草稿不能输出 Word；通过。 |
| 共用目录 | 相同分页参数的 MCP 与网页 API JSON 完全相同；通过。 |
| 实际网页 | 登录合成账号、确认新增研究方向、生成 2025 年草稿、上传 Word 模板并实际下载；通过。 |
| Word | 姓名、单位、职称与 80 学时来自同一草稿；行政职务为空；人工备注保留；非正文 ZIP 部件未变化；通过。 |
| 视觉检查 | 最终 Word 渲染为一页，中文正常、无遮挡；实际网页下载文件与已渲染检查文件 SHA-256 相同；通过。 |

协议验收的候选由固定测试程序提交，验收程序以合成用户会话确认；这验证接口约束和状态流转，**不是 WorkBuddy 模型抽取准确率测试**。实际网页另外确认了一条候选。Word 中的事迹段落是预设模板套用有据字段，没有在本轮验证模型自由撰写长篇个人事迹。

## 复现

先按 README 启动数据库、API 和 Worker。命令会创建新的本地合成账号，不接触真实用户资料；指定尚未使用的实验目录，避免覆盖原验收凭据。

```bash
uv run pytest
uv run python scripts/check_migrations.py
npm run build --prefix web
AKB_ACCEPTANCE_DIR=work/knowledge-layer-rerun uv run python scripts/verify_knowledge.py
```

输出的 `results/verification.json` 必须全部检查为 true，`workbuddy_model` 仍应为 `NOT_RUN`。`private/session.json` 仅供本地实验，权限 0600，禁止提交或分享；不再演示时应撤销相应测试令牌。重复使用同一个实验目录会拒绝覆盖。

本轮演示保存在 `work/knowledge-layer-e2e/`；最后协议复现保存在 `work/knowledge-layer-final-regression/`，后者的令牌验收后撤销。对外交付仅复制不含凭据的报告、目录、截图和文档。

## 当前限制

原文包含值、人物和日期的检查可以拦截已知误用，不能证明任意自然语言语义成立，因此保留候选审阅。事项去重依赖 Agent 提供稳定 entity_key，目前只规范空白和大小写；不同写法是否同一论文/项目，仍需主体判断和用户核对。

知识目录当前按类别展示事实及依据，重复来源的事实仍可同时展示，统计时才按事项去重。大库读取与筛选仍需性能优化，未声称支持任意规模。现有解析器的部分覆盖、OCR 和原生空间账本限制继续有效，见原专项记录。

Word 自动填写要求预先标记位置，模板限 10 MiB；资料入库单文件上限仍为 2 GiB。任意无标记 Word、自由写作、真实第三方网页提交，以及持续主动的网络补全不属于本轮已验收能力。
