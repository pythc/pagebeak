## 当前实现

开始页主按钮“在 WorkBuddy 安装 · 本机测试”通过受登录、CSRF 和频率限制保护的 POST 创建私有接入包，并打开 WorkBuddy 5.8.3 支持的 task 深链。客户端准备好安装请求后，由用户发送。用户不再复制文字。深链只含任务指令、可信项目安装器与本机包路径，不含短期码或长期凭据；使用正常权限模式和本项目工作目录。

安装器将包注册到 WorkBuddy 自定义专家目录 `plugins/marketplaces/my-experts/plugins/`，合并专家市场清单。只有 WorkBuddy 实际注入创建会话 ID 时才写相应标记，不伪造会话、信任记录或授权。由宿主继续召唤专家和处理 MCP 依赖确认。本机安装器不直接改 mcp.json，避免旧路径的内存快照问题。

开始页另有固定入口“打开管家并开始初始化”，刷新后仍存在。它用本机客户端实际支持的 `expertId` 参数选中对应专家，同时填入绑定本库的初始化请求；用户在 WorkBuddy 发送并按宿主提示授权。不能只把普通任务深链加上管家名字就称为已召唤，也不依赖临时详情面板或让安装任务生成模拟专家卡片。

包内含专家定义、初始化入口、所有 personal-knowledge Skill 引用、品牌图标和根目录 .mcp.json。采用官方支持的根目录 MCP 依赖回退格式，避免 WorkBuddy 专家 dependencies 对象与通用 CLI dependencies 数组的格式差异。分类使用本机 5.8.3 支持的 04-DataAI，中文名称为“知序知识库管家”。

## 账号与凭据

- 包按知识库 UUID 绑定，使用独立的 `zhixu-<UUID>-expert`，保留旧连接。
- 只有本人网页会话能生成包。首次码 15 分钟有效、一次使用；重新生成仅作废未兑换码，不撤销已有有效连接。
- 首次 MCP 进程启动时兑换并核对库 ID，将长期凭据以 0600 写入本人 0700 的 `~/.zhixu-connectors/`。长期凭据不进入分发包、技能或任务深链。之后重开无需再次兑换短期码。
- 临时网络失败不会旋转凭据或消费新码。撤销后需生成新包；私有凭据写入失败时撤销刚签发的令牌。
- 运行回执记录 expert 渠道；下载、注册、运行和实际 start_onboarding 核验分别记录。接口不替模型编造个人回答。
- 安装只接受当前项目生成的已核对文件，拒绝路径穿越、额外脚本、其他启动命令、符号链接和未托管的同名专家。重复安装及短期码更新保留原注册内容；已有人工作修改时停止。注册失败回退，保留备份。
- 启动包仅保存在本机私有目录，首次码和 zip 不对外公开。过期临时包在下次生成时清理，不清理用户资料或专家已安装文件。

## 本地验证命令

保持 `scripts/dev.py` 运行后执行：

```sh
.venv/bin/python scripts/smoke_workbuddy_package.py
```

## 正式分发仍需完成

正式入口采用已发布专家的安装深链，由 WorkBuddy 的专家依赖引导统一安装 MCP 与 Skill。现已核对本机客户端支持的 `codebuddy-ide/expert/install`、专家名称与 sharecode 参数；构造器仅接受明确提供的发布身份，不生成假分享码。尚无发布资产，页面明确显示市场版待发布，接口 one_click_ready=false。

正式发布需要开发者账号、真实作者联系信息，以及面向不同用户和不同电脑的远程 HTTPS MCP 与账号授权。当前本地 API 和 stdio 依赖本项目 Python 环境，不能直接作为公共市场包；带短期码的私人验收包也禁止上传市场。需要将用户无关的公共包与用户授权绑定分离，优先使用官方 MCP OAuth 2.1 + PKCE 流程。

依据：[官方专家规范](https://open.workbuddy.cn/en/docs/expert)、[连接器认证与分发规范](https://open.workbuddy.cn/docs/connector)。当前深链参数与本机注册路径另与已安装 5.8.3 的代码和自带专家管理脚本核对，未承诺其他宿主版本均兼容。
