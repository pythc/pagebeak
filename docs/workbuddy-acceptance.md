## 修复与验证

完整流程检查发现：原代码在保存生成目录时递增事实版本，导致先生成的表单误判失效。已移除这一次无关版本递增，并保留租户锁和证据校验。事实确认、原始资料变化和撤回仍会使旧草稿失效。

新增回归测试在修复前实际失败，修复后全部 **22 项测试通过**；Ruff 检查和 TypeScript/Vite 构建通过。真实客户端执行“先生成草稿、再保存目录”后，API 再读确认新草稿仍为 `stale=false`，五项答案保留。

浏览器自动化期间曾发生异常粘贴，一条系统剪贴板中的无关脚本命令进入原对话。已停止该对话并重建控制连接；回看 WorkBuddy 记录显示“已取消”及“我没有执行这条命令”，另有只读复核说明。本项目未执行该脚本，也未对其所属项目继续操作；未将 WorkBuddy 对该项目的其他结论当作已独立核实的事实。后续在独立任务完成本次验收。不要用原生编辑菜单代替已校验内容的自动化粘贴，也不要直接设置 React 富文本输入区的底层值。

## 证据与复现

原始证据保存在本聊天 `outputs/workbuddy-e2e/`：

- `02-before-confirmation.json`：确认前资料、档案、专题和草稿。
- `05-verified-source-evidence.json`：经 API 重读的引用原文及定位。
- `06-after-confirmation.json`：确认后的五项事实、两个专题及新旧草稿。
- `08-workbuddy-final-result.ax.txt`：实际客户端完成回复。
- `form-actual.png`：从 WorkBuddy 导出的原始浏览器截图，未重绘或补填。
- `verification.json`：验收状态、资源 ID、测试结果与文件校验值。
- `继续验收指令.txt`：第二轮实际使用的不含答案与凭据的指令，可在已有合成账号中复现。再次运行会新建专题和草稿。

本轮实际使用了 9 类 MCP 工具；`propose_profile_facts` 未在真实客户端调用，因为标签抽取已生成候选。工具发现 10 项不等于逐项实际执行 10 项。
