# 恢复 Cloudreve 原版前端

日期：2026-10-17。

后续状态：本记录保留恢复原版当时的结果；当前已按用户指定移除五个侧栏入口、更换徽标并完善目录树，见 [最新验收](native-frontend-customization.md)。下文“未修改原版”仅指恢复阶段。

用户指出自建文件页面不符合预期，要求先恢复原版，再自行指定保留、移除和新增功能。本轮仅恢复原版界面基线，不继续自主裁剪。

- “我的文件”入口直接跳转到本机 5878 端口的 Cloudreve 原版页面，独立显示，不套自建文件管理界面。
- 从前端工程移除 `FilesView.tsx` 和对应自定义文件页样式。修改前的界面代码备份在被忽略的 `work/native-frontend-restore/`。
- 使用镜像自带的原版前端与原生中文语言资源，没有修改其组件、布局、菜单或主题。
- 恢复 Cloudreve 站点名称并设置正确的本机站点地址，保留原生菜单。
- 使用独立的非管理员界面评审账号与上游默认普通用户权限，包含四份合成办公材料。没有把后台共享存储账号交给浏览器，也未改变知识库已有文件、个人配额或人工修改。

原版界面：[http://localhost:5878/](http://localhost:5878/)。知识库仍在 5876 端口运行。当前两者是独立登录与数据入口，**原版界面新上传不会自动进入知识库**，待确认功能范围后继续做账号与文件同步。当前是界面评审基线，不声称已完成原版 UI 的全业务集成。

实际验证：

- TypeScript 与 Vite 构建通过；构建中已无自建文件页模块。
- 浏览器从知识库“我的文件”进入原版 `/session`，登录隔离演示账号后到达原版 `/home`。
- 原生侧栏显示我的文件、图片、视频、音乐、文档、与我共享、回收站、我的分享、连接与挂载、后台任务及容量。
- 原生新建菜单显示上传文件、上传目录、剪贴板上传、文件夹及新建文件等选项。
- 浏览器实际上传合成 Word、Excel、PPT、PDF，四份均显示“已上传”，关闭上传队列后原生文件列表可见。
- Python 引导脚本 Ruff 检查通过；本轮没有改动知识库后台业务，未重新执行后台全量测试（`NOT_RUN`）。

演示凭据保存在 Git 忽略的 `secrets/cloudreve-review.json`，权限 0600，不写入导出材料。没有删除原件、降级数据库或部署生产。
