# 首次接入与初始化

当前问法已修正为安装后在同一对话直接了解需求、允许合并询问和批量保存，不要求回网页点击初始化。见 [修正与验收](onboarding-conversation.md)。以下逐题描述仅代表早期实现，不再是使用要求。

当前主入口已集成到原生文件空间 `/start`，见 [原生开始页与验收](native-start.md)。以下保留首次接入功能和历史验收。

日期：2026-10-17。当前为同一台 Mac 上的本地开发版，主入口已改为从页面唤起 WorkBuddy 安装本机接入包，原复制接入文字作为兼容路径保留。不是任意网页大模型的一键安装，也未发布云端连接器。

后续用户确认先完成接入包与本地验证。新的主入口直接唤起 WorkBuddy 安装本机专家包，不再要求复制文字；原脚本降为兼容入口。包由专家、Skill 与 MCP 依赖组成，首次运行才绑定本人库。市场发布版仍待开发者资产和远程授权，详见 [一键接入](workbuddy-one-click.md)。下文复制指令流程保留为兼容路径的历史与验证记录。

## 兼容路径与既有页面行为

新用户创建空资料库后默认进入“开始使用”，既有有资料的账号继续进入目录，不强迫重新初始化。侧栏始终保留开始入口；“先看看资料库，稍后继续”保存跳过引导的选择，已有回答不清除。注册显示名称改称“空间名称”，避免与正式身份混淆。

1. 页面解释用途，主按钮为“复制接入指令”。不要求用户理解 JSON、令牌、MCP 或 Skill。
2. 用户在同一台电脑打开 WorkBuddy，新建对话并粘贴。接入文字只含短期一次性码、本机安装器路径与明确范围，不包含长期 API 令牌。
3. 安装后，页面进入“安装已完成，等待助手核验”，提供准确的连接名称及绑定当前库的继续指令。在自定义连接器管理中搜索该名称；列表没有时，先从 WorkBuddy 菜单完整退出并重新打开，让宿主读取外部写入的配置。出现后按实际提示由用户确认信任，再在输入框“＋ → 连接器”选用并发送继续指令。管理列表已出现而工具仍不可见时才尝试新对话。
4. 助手核对库 ID，执行当前 Skill，并通过 start_onboarding 核验。页面到此才显示连接已核验；复制文字、兑换接入码、写入配置都不会使它提前变绿。
5. Skill 一次询问称呼、目前工作/学习身份、优先用途。可明确跳过，也可中断后继续；用户当前对话已说明的内容不重复问，不从空间名称猜身份。
6. 回答或明确跳过三项后展示基础摘要，再邀请上传一份材料试用。没有资料时仍明确提示添加第一份，不把基础引导完成说成资料已经可检索。

页面提供文件上传、共用目录入口和连接失败时的手动设置。原“连接 WorkBuddy”页面继续作为高级入口；Cloudreve 原版文件管理页面及现有数据保持原样。

## 实现与权限

- 迁移 0015 增加 onboarding 和 connection_tickets，两表启用并强制租户 RLS，既有租户回填空初始化状态；0016 增加独立安装收据，和实际助手核验分开。
- 接入码 15 分钟有效、数据库只留摘要、串行兑换且一次使用；重新生成会使之前未用的指令失效。签发它的浏览器会话失效后不能兑换。错误库 ID 不能消费正确码。
- 浏览器主动点击生成指令即授权本库连接，兑换只签发既有四类业务权限；不能确认个人事实、批准删除或替用户提交外部表单。安装失败时尝试撤销本次新凭据。
- scripts/install_workbuddy.py 使用本项目已有 Python 环境，不下载/执行远程脚本，不读取 WorkBuddy 登录凭据。备份并合并 mcp.json，按库 ID 命名连接，权限 0600；其他服务及顶层配置保留。同名非本安装器连接、非托管技能、异常 JSON、符号链接、安装期间配置变化均停止，保留原状。
- Skill 复制到 ~/.workbuddy/skills/personal-knowledge，已有托管副本先备份；不覆盖未经安装器管理的同名技能。安装收据不含令牌。
- 安装器不对已有目录重复 mkdir，技能先复制到尚不存在的暂存子目录。兼容修复保留宿主拦截，不改变保护环境；真正权限拒绝立即停止。配置、技能和收据一起回退，失败的新令牌撤销。--check 只核对已有配置并向页面回报，不重新兑换接入码，也不代替 MCP 调用。
- 新增 read_onboarding、start_onboarding、update_onboarding，共 32 个 MCP 工具。进度以 expected_revision 更新，409 后重读；记录称呼、身份、用途和跳过项，不保存完整聊天。正式个人档案仍须原始声明/资料、候选和用户复核。
- “连接已核验”表示该凭据曾实际调用初始化 MCP 且仍有效，不等于 WorkBuddy 常驻在线。Skill 是否作为宿主插件自动发现、是否能在同一对话热加载，仍受客户端控制；接入文字要求读取指定 Skill 后执行，不允许用直接 HTTP 假装 MCP 成功。

官方文档支持本地 stdio MCP 与 Skill 组合，以及技能包导入；没有承诺一段文字就能在所有客户端完成无交互安装。这里的本机安装器、一次性码、进度与失败恢复由本项目实现。[WorkBuddy 连接器](https://open.workbuddy.cn/docs/connector)、[Skill 格式](https://open.workbuddy.cn/docs/skill)、[用户安装入口](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Skills-Market)。

## 用户试用后的安装恢复修正

用户粘贴了实际试用对话：安装先报权限错误，助手尝试改变保护层或启动方式后报告成功，随后工具仍不可见。现场检查确认目标 fb52eafb… 的配置和托管 Skill 存在，API 身份核对成功，文件权限为 0600，其他连接仍在；但 started_at 为空，不能宣称已完成助手接入。该安装器由本项目维护，并非 WorkBuddy 官方脚本。

目前没有独立复现 WorkBuddy 内部拦截层的确切缺陷，因此不把对话中的 PYTHONPATH/sitecustomize 归因当作已证实事实。回归测试模拟“对已有目录 mkdir 被拒绝”验证兼容场景，并在拦截保持开启的条件下通过；真实权限拒绝仍停止，不采用关闭保护或改变启动环境的办法。

本轮用 --check 核对用户已装好的目标连接并回报安装收据，核对前后实际 mcp.json 哈希相同，没有重装、没有使用接入码，也没有调用 start_onboarding 冒充助手。开始页现在显示“安装已完成 · 等待助手核验”，并可分别复制连接名称及包含确切库 ID 参数的继续指令。继续指令提供可展开的手动复制文本。需要在 WorkBuddy 选用并实际调用后才变为已核验。

接入指令与 Skill 同步约束：失败时停止并简短说明，使用宿主正常授权；不改安全注入、启动保护、信任记录或安装器源码。恢复说明不再让用户阅读长篇调试报告，不把写入配置说成工具已加载。根据[官方连接器使用说明](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Connector)，可在任务输入框选用连接，某些按需连接可继续当前任务；不能一概断言“只有新对话才会加载”。

本轮证据在 work/onboarding-recovery-20261017/。宿主实际选用和新模型初始化仍待用户在 WorkBuddy 完成，当前未通过直接调用接口推进个人回答或制造接入成功状态。

## 连接列表未刷新的现场排查

用户反馈在管理界面找不到目标名称后，核对发现：WorkBuddy 5.8.3 的主进程在 06:34 启动，目标配置于 07:40 写入。只读检查当前安装包的 UserMcpProvider 显示，collect/list 使用 lastGood 内存快照，初始化、显式 refresh 或保存配置才更新；读取配置文件本身不会提交新快照。这解释了“文件存在”不能证明“列表已出现”。

通过客户端正常退出再重开后，实际截图中“我的 MCP”从 7 项变为 8 项，目标 zhixu-fb52eafb… 出现在第 5 项，显示首次信任提示。其余三个旧知识库连接重新发现 32 个工具。未修改实际 mcp.json 或信任记录，未重新兑换接入码。目标首次信任、实际 MCP 核验与初始化访谈仍未完成，不把列表出现当作连接已授权。

开始页、生成指令和安装器提示已补上“管理列表缺失时完整退出并重开”的恢复分支；新建对话不能代替管理器重新读取配置。证据在 work/onboarding-connector-investigation-20261017/。这一结论针对本机 5.8.3 的实测，不代表所有宿主版本都没有文件热加载。

正式新手入口应使用 WorkBuddy 支持的连接器或插件分发，将 MCP 与 Skill 打包并由宿主管理安装和授权。当前尚未提交市场审核，也没有验证任意自定义服务的通用一键安装深链；本地脚本不能标为正式一键接入。[插件说明](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Plug-In)、[连接器提交与认证规范](https://open.workbuddy.cn/docs/connector)。
