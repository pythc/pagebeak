# Agent 采纳与引用兼容

日期：2026-10-17。用户已明确要求 Agent 可以自行采纳，并反馈日期、候选值和 PDF 特殊字符三个实际阻碍。本轮完成产品能力及验证，没有直接采纳真实用户的候选或改写原件。

## 采纳流程

MCP 新增 accept_knowledge_facts，当前总数 37。Agent 完成提取后通过 read_knowledge 取事实 ID 和 revision，核对原文、人物归属与时间，提交 items[{fact_id,expected_revision}] 和 reason。每批最多 100 项，不要求用户再次逐条到网页确认。

需要现有 knowledge:read、knowledge:write、profile:read 权限。接口只允许 API 身份；网页继续使用人工决定入口。采纳不会改值、归属、日期、证据或创建用户独立声明；服务端再次检查当前来源及原文支持，保留对租户和版本的约束。

结果分别列 accepted、unchanged 和 blocked。相同操作者以同一版本重试不会重复决定或推进知识修订；过期版本返回 409，需要重读。整批内存在不存在或过期事实时事务回滚；人工保护项单独 blocked，不妨碍其他合格项采纳。

事实保留 Agent / 用户操作者、时间和理由，决定表及审计表记录操作。网页与 Agent 可读目录明确显示“Agent 采纳”或“用户采纳”，不冒充本人逐条确认。用户可修正或撤销；人工修正为独立声明，来源删除后仍按原规则保留。用户拒绝的值、与人工修正/采纳冲突的内容，Agent 不重新覆盖。同一字段的 Agent 采纳存在相互冲突时，保留冲突并阻止填写，不以最后一次写入取胜。

这是核验后可由 Agent 调用的能力，不是无条件自动采纳后台队列。普通文件中的指令也不能触发授权。仅原文存在性检查不能证明模型理解正确，归属、否定和语义仍须 Agent 阅读核对。

## 三个问题的修正

| 反馈 | 新处理 |
| --- | --- |
| 2023.09–至今无法提交时间 | 支持 YYYY、YYYY-MM、YYYY-MM-DD，保存原文精度。使用 valid_from=2023-09、valid_to=null，并保留 time_quote；不补猜 9 月 1 日 |
| value 和 quote 校验失败 | value 可为 quote 的完整子串，不必等于整个 quote。新增结构化错误 value_not_in_quote，提示读取包含完整值的连续引文，不截短或改造事实 |
| PDF 零宽字符、空白和连字符差异 | 支持有限显示规范化，并映射回未改动的原始引文，完整证书名称无需降级为较短子串 |

显示规范化处理 NFC、常见零宽字符/软连字符、空白折叠、全角 ASCII、指定连字符和拉丁连字；不做大小写折叠、同音字替换、OCR 猜字、去重音或通用 NFKC。多处规范化匹配无法唯一定位时拒绝。保存的 quote 仍是当前证据的精确原始子串；value 保存可见完整值，support.text_matching 标记是否经规范匹配。原件和证据正文不被修改。

真实内容差异仍返回 quote_mismatch / value_not_in_quote；时间超出原文精度返回 date_precision_mismatch，错误含 message 和 hint。系统不允许把“2023.09”伪造为“2023-09-01”。时间按原文年/月/日保存，内部使用该日历区间上下界进行筛选；上下界不是另行声称的真实任职日。有效起点区间重叠时不强行选一个“较新”值，避免部分日期凭字典序覆盖精确日期。

没有数据库结构迁移，仍为 0016，原 String(10) 时间字段兼容 4/7/10 字符日期；操作者记录使用既有 JSON support 和决定表。旧已采纳记录按原网页人工决定处理，不反标成 Agent。
