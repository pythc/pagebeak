# 统计与填写可靠性修正（2026-10-25）

本轮针对上一轮真实盲测暴露的四类错误：无关记录阻塞统计、把数量填入名称字段、金额单位不一致，以及事迹改写改变事实含义。实现已经完成；新的 WorkBuddy 盲测结果单独记录，不能用自动化回归代替模型验收。

## 已实现的行为

| 问题 | 处理方式 | 保留的限制 |
| --- | --- | --- |
| 统计被拒绝记录、无关年份记录干扰 | 不再把 rejected/superseded 记录加入分组；任一已确定的筛选条件不符合即排除，无关字段未知不阻塞本次统计 | 相关记录的状态未知或冲突仍阻止统计；事项去重仍依赖正确 entity_key |
| 名称与数量混用 | 结构化填写字段必须提供目标契约 target，核对查询字段、操作、筛选、事项和时点，并验证目标数据类型 | 任意网页的含义仍由调用者读取；如果查询与契约同时理解错，服务端无法单凭标签识别 |
| 单值金额未转换或丢失单位 | 单值与求和统一使用 Decimal；明确输出元或万元；保留原值、标准值、目标单位和未舍入标记 | 拒绝含糊金额、非法千分位、单位冲突；不处理币种汇率或把批准额解释成到账额 |
| 写事迹时扩写事实 | narrative.field_keys 引用同一草稿的普通字段；服务端生成保守表述，每句绑定事实与证据，保留筛选范围和单位 | 属于受控表述，不是自由润色的通用语义验证器；已有人工正文不自动认证 |
| 草稿正确但最后填写被改写 | validate_form_output 精确核对全部字段；未知字段必须空白；拒绝漏字段、多字段、改值和过期草稿 | 校验仅证明传入值一致；必须从实际网页或 Word 回读，才能证明最终产物一致 |

## 接口及升级

- `prepare_form` 的结构化字段新增 `target={knowledge,value_type,unit}`。count 使用 integer；金额、学时和人次必须明确单位。详见技能 `references/semantic-tasks.md` 的例子。
- 新 MCP 工具 `validate_form_output(draft_id,values)`；HTTP 为 `POST /v1/forms/drafts/{id}/validate`。沿用所属租户、限权令牌、CSRF 和 forms:write 权限检查。
- `narrative={field_keys:[...]}` 只可引用同草稿中不重复的普通字段。依赖未就绪则整个段落阻止填写。
- 填写规则标识为 `form-evidence-v2`。旧草稿即使来源修订不变也标记 stale，要求重新生成；旧结构化调用未提供 target 时返回 blocked。普通六字段档案调用仍兼容。
- WorkBuddy 接入包版本为 `0.5.0`，MCP 工具总数为 38。已有连接需要重新加载工具描述；没有自动改动用户的已安装技能副本。
- 无数据库迁移，不删除原资料或人工修改。若回滚到旧程序，旧程序不会执行新增的契约/输出校验，不应继续将本轮结果视为受新规则保护。
