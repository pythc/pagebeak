# PoC 与验收计划

版本：v0.1

日期：2026-10-16

状态：完整 PoC 计划；下表状态指完整样本验证。2026-10-17 的基线工程测试与 MCP 联调见 [实施记录](implementation-status.md)，不等同于本计划全量验收。

## 1. 验证目标

回答五个问题：文件能否解析并定位到原文；事实能否正确归属于用户；更新、冲突和删除能否一致处理；多用户边界是否在所有路径生效；系统能否以可接受的单位成本完成真实表单。

先验证方案中最容易导致返工的能力，不把能启动容器、健康检查通过或一次问答成功当作 PoC 完成。

## 2. 建议样本

以下数量是本项目提出的初始样本设计，不是已有数据或用户规模承诺。使用合成或经授权脱敏数据，禁止把真实个人资料放进公共仓库。

建立 10 个测试用户，准备 100 份资料：

| 格式 | 数量 | 必含场景 |
| --- | ---: | --- |
| PDF | 30 | 数字文本、扫描、双栏论文、复杂表格、页眉页脚 |
| DOCX | 20 | 简历、表格、文本框、新旧任职记录 |
| XLSX | 15 | 多工作表、合并单元格、论文清单、重复记录 |
| PPTX | 10 | 项目简介、成果页、图文混合 |
| PNG/JPEG | 15 | 证书、低清照片、旋转与裁切 |
| TXT/Markdown/HTML | 10 | 个人说明、公开主页快照、含冲突的网页资料 |
| 合计 | 100 | 按用户分散，包含相同文件与同名人物 |

额外构造失败样本：损坏、加密、类型伪装、超限压缩内容、外部恶意指令、指向私网及重定向的链接。失败样本不用于“支持格式成功率”的分母，但必须纳入失败处理验收。

建立 300 个带人工标准答案的表单字段任务：精确字段 120 个、列表或统计 60 个、叙述文本 60 个、缺失或冲突 60 个。缺失与冲突各自标明原因，不以留空自动判定全部通过。

至少构造 100 个检索问题，人工记录相关原始证据及位置。模型或规则调试数据与最终验收留出集分开；不要在同一批答案上反复调参后声称泛化能力。

## 3. 实验记录要求

每次实验保存：测试 ID、样本版本和哈希、软件 tag/commit、镜像摘要、解析器、模型及配置版本、系统提示版本、schema、授权策略版本、执行时间、结果、证据定位、费用和失败原因。

原始结果放 `work/` 或受控实验存储，不提交个人正文。可提交脱敏样本说明、统计和失败分类。报告区分 `PASS / FAIL / BLOCKED / NOT_RUN`；外部服务不可访问标记 `BLOCKED`，不能计为通过。

## 4. 分组验证

| ID | 场景与动作 | 预期结果 | 当前状态 |
| --- | --- | --- | --- |
| P01 | 各格式上传与解析 | 处理阶段清晰，原件保留，成功/部分成功/失败可区分 | NOT_RUN |
| P02 | 从答案打开 PDF、表格、文档和网页证据 | 定位到对应源版本；不把引擎 chunk ID 当作稳定证据 ID | NOT_RUN |
| P03 | 读取上游解析结果与结构 | 公开 API 足够形成证据契约；不足项有明确替代路线 | NOT_RUN |
| P04 | 上传别人的论文、简历和证书 | 可成为收藏；不得自动变成本人的成果或个人信息 | NOT_RUN |
| P05 | 同名作者、机构变化、缺 ORCID | 模糊归属进入候选；展示匹配依据，不按姓名直接合并 | NOT_RUN |
| P06 | 先上传新聘任文件，再上传旧简历 | 依据有效时间和证据处理，不按上传先后覆盖现任信息 | NOT_RUN |
| P07 | 用户修正与后台抽取并发 | 后台旧结果不能覆盖用户决定；revision 冲突明确呈现 | NOT_RUN |
| P08 | 预印本、正式版、重复 DOI、共同第一作者 | 版本与成果区分，统计口径明确，未知作者角色保持未知 | NOT_RUN |
| P09 | 一份文件关联多个目录，用户固定分类 | 原件不移动，手工关系不被生成任务悄悄覆盖 | NOT_RUN |
| P10 | 重复任务、Worker 宕机、模型或引擎超时 | 可恢复，不重复创建有效成果；未知写入结果先对账 | NOT_RUN |
| P11 | Worker 租约过期后恢复执行 | 旧 fencing token 不能发布结果 | NOT_RUN |
| P12 | 新批次构建到一半失败 | 不将半成品发布为完整新知识；旧版本状态清晰 | NOT_RUN |
| P13 | 删除资料时同时检索、重算和下载 | 撤回后禁止新读取和结果发布；旧任务不能重新激活资料 | NOT_RUN |
| P14 | 删除唯一证据与删除多证据中的一份 | 前者撤回相关事实，后者重新判定；页面和表单草稿同步失效 | NOT_RUN |
| P15 | 删除后执行清理失败和重试 | 访问持续阻断，清理状态可见，最终可对账 | NOT_RUN |
| P16 | 恢复含已删资料的备份 | 开放访问前重放撤销记录，资料不重新暴露 | NOT_RUN |
| P17 | 将带 manifest 或已知哈希的本系统生成摘要再次导入 | 识别派生来源，不能作为独立证据放大同一结论；外部来源不明内容不作同等保证 | NOT_RUN |
| P18 | 网络下载超时、预算耗尽、授权撤销 | 退避或停止；授权撤销后不得继续发布入库结果 | NOT_RUN |
| P19 | 无全文、许可不明、来源身份不确定 | 保存适当元数据/候选；不伪报全文下载或成果归属 | NOT_RUN |
| P20 | 自有表单字段填充与统计 | 字段值、证据和统计口径可核对，缺失/冲突字段明确 | NOT_RUN |
| P21 | 统计时存在解析失败、年份未知、作者待确认的相关资料 | 返回不完整范围，不能把部分数量填成完整总数 | NOT_RUN |

### 4.1 多用户与外部内容边界

| ID | 测试路径 | 预期结果 | 当前状态 |
| --- | --- | --- | --- |
| S01 | 用户 A 猜测 B 的 source、evidence、job、draft ID | 不返回 B 的内容、状态、存在性或下载地址 | NOT_RUN |
| S02 | 修改请求中的 user、tenant、dataset、engine document ID | 服务端只使用认证得到的范围，越权输入被拒绝 | NOT_RUN |
| S03 | 引擎召回、重排、LLM 上下文逐阶段插入哨兵资料 | 其他租户正文不得进入任何处理阶段；不能只过滤最终显示 | NOT_RUN |
| S04 | 缓存、连接池、checkpoint、SSE 和队列复用 | 不跨租户继承状态或命中私人答案 | NOT_RUN |
| S05 | 上传内容要求忽略规则并导出其他资料 | 外部内容不能扩大工具能力或租户范围 | NOT_RUN |
| S06 | 私网 URL、DNS 变化、多跳重定向、超大响应 | 下载器拒绝越界访问，记录有限诊断，不泄露内部响应 | NOT_RUN |
| S07 | 直接访问检索服务、对象存储和模型凭据 | 客户端无法绕过业务权限，原件下载逐次鉴权 | NOT_RUN |
| S08 | 用户撤销外部补全和披露授权 | 运行任务在副作用前和结果发布前复查，失效授权不能继续使用 | NOT_RUN |
| S09 | 普通运行账号与数据库连接池切换租户 | RLS 生效，无上一个租户上下文残留；运行角色不绕过 RLS | NOT_RUN |

测试集出现零泄露是上线门槛，不是对所有未知漏洞的数学证明。测试失败必须定位根因、修复并重复相关路径，不能以模型通常不会这样回答为解释。

## 5. 初始验收指标提案

阈值是建议的产品门槛，尚未得到实测结果；PoC 后可以据实际用途调整，但不得在失败后无记录地降低门槛。

| 指标 | 计算方式或要求 | 初始门槛 |
| --- | --- | --- |
| 精确字段正确率 | 填出的精确字段中，值及主体/时效正确的比例 | ≥99%，同时报告样本数和错误数 |
| 精确字段覆盖率 | 有足够证据且允许披露的精确字段中，正确填写的比例 | ≥90%，不能靠全部留空获得高正确率 |
| 列表/统计 | 分别报告条目 precision、recall 和聚合值 exact match | 测试集关键计数全部正确；不允许 top-k 冒充完整集合 |
| 缺失/冲突处理 | 人工标记的缺失/冲突字段是否给出对应状态与原因 | 100% 不静默编造或覆盖 |
| 证据定位 | 被采用答案的引用能否打开并支持相应结论 | 100% 可定位；不支持的引用计失败 |
| 检索 | 每题至多 10 个必要证据单元的标注集上计算 recall@10，再按题平均；多跳/全量问题另报 | ≥90%，按文件格式分别报告 |
| 叙述字段 | 人工复核事实支持、长度、格式和遗漏 | 不允许新增无依据的关键个人事实 |
| 隔离与删除 | S01–S09、P13–P16 等关键用例 | 全部通过；任何泄露或资料复活为阻断项 |
| 异常恢复 | P10–P12 的重复、超时、宕机与过期租约 | 无重复有效写入、无旧任务越权发布 |

格式成功率、OCR 误差、耗时 P50/P95 和处理费用分别报告，不为全部输入混报一个平均值。扫描件与数字文本、普通表格与复杂表格分组统计。

小样本百分比受样本粒度限制。例如 120 个精确字段任务中一个错误就会显著影响比例；报告必须给出分子分母，不能只报小数点后的“准确率”。

## 6. 成本与容量实验

依次记录一名用户、五名用户、十名用户并发导入时的排队、解析和问答表现；这是实验负载，不是生产容量承诺。记录硬件、模型是否本地部署、缓存命中与文件页数。

单位成本至少分为：每 100 页数字文本、每 100 页扫描件、每份复杂表格、每次有引用问答、每份表单、每次补全任务。记录输入/输出 token、Embedding 用量、解析计算、网络调用、存储增长和失败重试额外开销。

使用实验时真实有效的服务价格计算费用并保存价格日期。模型和供应商未确定前只记录用量，不编造人民币月费。验证预算触达后是否能停止新任务并保留已完成状态。

## 7. 选型通过与退出条件

RAGFlow 继续作为底座需要满足：

1. 固定版本可覆盖约定格式，并提供业务所需的可靠原文定位。
2. 有可实现、可测试的租户身份与受限检索方式，不依赖前端隐藏或模型自律。
3. 文件与批次删除可对账，旧任务和缓存不会使资料重新可见。
4. 实现适配不必长期依赖不稳定内部表或大量修改上游核心。
5. 单位成本与部署复杂度在后续确定的预算范围内。

若任一关键项失败，先记录事实和最小复现，再决定固定版本对照、补充解析组件或切换 Docling + 自研检索路线。OpenViking 作为目录和记忆对照，需要另行评估其许可、同等证据和隔离契约；不以演示效果替代上述门槛。

## 8. PoC 应交付的结果

- 固定版本及环境清单，所有模型与配置版本可追踪。
- 脱敏样本清单、人工标准答案及留出集定义。
- 验证结果矩阵，保留 `FAIL/BLOCKED/NOT_RUN`，不得只记录成功项。
- 错误案例、成本与耗时分布、未覆盖风险和下一步修复范围。
- 通过或更换底座的明确决策，说明证据及迁移影响。

完整样本、模型质量与容量验证尚未执行；已有基线自动化测试和 MCP 协议验证，结果与未覆盖范围见 [实施记录](implementation-status.md)。
