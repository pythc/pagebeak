# 本机文档接入与验收（2026-10-26）

## 已确认的范围与实现

用户选择“本地建立索引，重要资料按需入库”。接入包 0.8.0、MCP 契约 tencent-workbuddy-v5，共35个工具；新增8个本机工具。腾讯 Memory 继续保存唯一的知识页与长期记忆，本机 SQLite 只保存可重建的检索缓存和处理历史，没有第二套模型或事实引擎。

初始化在当前 WorkBuddy 对话中选择：不启用、具体目录、或个人主目录内的全部受支持文档。可以同时提供身份、用途和目录，不逐题盘问。自动收录与共享清单分别默认关闭，按用户明确选择设置。已有安装不覆盖人工技能，get_knowledge_context 会返回当前可信技能入口及刷新说明，开始页的恢复指令也读取当前入口。

“全部文档”指所选个人主目录内受支持的非隐藏文件；系统/Library/Applications/凭据/代码依赖/链接排除，其他账号与外置磁盘需另选具体目录。未扫描用户真实主目录，本次运行全部限定在新建合成验收目录。

## 数据路径

1. 本机 MCP configure_local_documents 保存范围与策略，返回实际根目录、排除项及预算；不自动扫描或上传。
2. start_local_scan 返回任务 ID，独立有限进程枚举、哈希并解析，使用现有 Office/PDF/OCR 原文位置；新会话可继续增量检查。超时的解析在子进程结束，不阻塞整个 MCP 会话。
3. SQLite FTS5 对中文按字规范化并使用短语查询，原文与查询流分开保存，姓名、学位等短词可命中。没有生成式模型、向量模型或逐文件模型调用；原文开头摘录明确标为摘录，不冒充模型摘要。
4. search_local_documents/read_local_document 按需取片段，读取前校验当前原件哈希，拒绝越界及链接。交给 WorkBuddy 的片段仍会进入其模型处理，不能称为完全不出本机。
5. import_local_document 只按自动收录策略或单次明确授权上传原件，使用现有分块上传、空间配额、SHA-256、归属及请求幂等；相同归属的同摘要原件去重。收录预算中的未完成预留保守计入，重试沿用原 request_id。
6. 等待解析、同步后 read_source 获取正式证据，再由当前 WorkBuddy 生成腾讯主题页、prepare_filling 计算、validate_filling 核验实际产物。

本机数据默认位于 ~/.zhixu/local/<knowledge_base_id>/index.sqlite，按库隔离、私有权限；device_id 用于共享清单。云端只保存经授权的文件名、相对目录、状态和摘要，不接受绝对路径、摘录或正文。文件管理“知识目录”展示最近同步的本机清单，正文阅读仍需要对应设备，不能由清单推断当前在线。

## 增量与人工保护

未变化文件复用索引；改名、复制、新增、修改、缺失和离线有本机历史游标。撤销目录或新增排除规则立即阻止继续读取，并隐去相关历史路径。遍历失败不当成删除；本机缺失或离线不删除云端已收录快照。

已经收录的本机原件内容变化后，最小的ID/哈希观察会同步至云端，使旧版本退出当前知识召回并拒绝正式证据与旧填写回执。此同步不依赖共享文件清单开关；该用途随原件收录说明。人工页保持 protected，不覆盖其正文、修订号或备注，另建关联补充页承载当前事实。

扫描有 queued/running/syncing 阶段，版本观察与清单同步结束后才完成。pending 表示云端尚未同步，必须恢复连接重试，不能报告所有端已一致。本机缓存中的缺失记录供历史检查，共享清单移除缺失项。
