# 在同一对话完成接入和初始化

日期：2026-10-17。用户指出之前的提示词把“一次只问一个问题”和“安装后回网页点击初始化”设为强制步骤，要求移除。

## 修正

这两个步骤是项目人为添加的流程约束，不是初始化 API 的要求。原接口本来就接受多个 answers 和 complete:true。此次修正 Skill、初始化参考、专家默认提示、安装任务、安装器返回的 next 说明、原生开始页及旧页面的恢复文案，避免各层相互矛盾。

正常路径变为：打开接入任务 → 安装 Skill/MCP → 在当前任务选用或按需连接指定 MCP → 核验知识库 → 结合当前对话了解用户 → 一并保存已提供的信息并完成基础引导 → 整理已有资料和共用目录。只问真正缺少的信息，可以合并询问，不规定每轮问题数；也不为了完成引导而阻挡正在做的任务。

不再要求用户回网页点击初始化、再次召唤专家或另开对话。网页用于接入和查看进度，“重新打开 WorkBuddy”等操作收进恢复区。只有客户端实际要求授权或连接确实失败时才提示相应操作。[WorkBuddy 官方连接器说明](https://www.codebuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Connector)也说明：任务中按需连接，完成授权后可继续当前任务，无需重新发起对话。这不证明本项目未发布的本机包在所有客户端版本都能自动加载。

`read_onboarding` 新增 `pending_questions`，一次返回全部缺项；保留 `next_question` 兼容已有客户端。`update_onboarding` 工具描述明确允许一次写多项并 complete:true。协议仍为 2026.10.17.1，无数据库迁移、不改变已有回答和凭据；新接入包版本为 0.4.0。

初始化仍只使用用户实际回答、明确跳过或可信对话里已提供的信息；不把登录名推断成身份，不把未答视为跳过，也不把引导回答直接当作已确认的填表事实。
